## 1. 概要

「公道レビュー」は、自分が実際に走った峠・スカイライン・海岸線・林道などの公道を残すためのWebアプリです。**自分専用の非公開の「道の記録帳」**として、ドライブの後に景観・路面状態・走りやすさ・交通量などの観点で振り返ります。

MVP（最初に出す最小限の版）は、**個人の非公開記録に限定**します。**速度・時刻・タイム・傾き角・ランキングは、保存も表示もしません。** 速度やカーブを攻めることを連想させる言葉も使いません。

## 2. 課題

- 走った道の記憶が写真フォルダ・SNS・メモに散らばり、「あの峠はどうだったか」を後から振り返りにくい。
- 既存のツーリング系アプリは、ルート計画やGPSの走行ログが中心。ユーザーが道そのものを採点する仕組みは、調査した範囲では見つからなかった（既存サービスの単位は「地点」「都道府県」「編集部のおすすめ」「自動の点数」のどれか。出典: CSO市場分析 4章・6章）。
- 冬季閉鎖・料金・二輪通行止め・トイレの有無など、次の計画に役立つ情報が手元に残らない。冬季閉鎖の解除日は道ごとに違う（例: ビーナスラインは2026年4月21日、磐梯吾妻スカイラインは4月下旬。出典: CSO市場分析 3章）。
- Google マップの移動履歴（タイムライン）はウェブ版が終わり、端末の中だけに保存されるようになった。走った道の履歴を残す場所がなくなった人がいる（出典: CSO市場分析 4章・5章）。

参考にする形は AllTrails の「登録済みの道（トレイル）＋日付付きの複数レポート」。

- 公開共有、他ユーザーのレビュー閲覧（CEO決定2。データの作りだけは将来に備える。7章を参照）
- リアルタイムGPS追跡、現在地への追従、「現在地へ移動」ボタン、走行中の操作を前提にした機能
- 速度・時刻・所要時間・区間タイム・傾き角・ランキング・集団走行の呼びかけ（**MVPに限らず、ずっと扱わない**）
- HEIC形式の写真（CEO決定5）
- メールマジックリンク以外のログイン方式（CEO決定3）
- 道路マスタの全ユーザー共有、GPXインポート、地図上に線を引く機能
- 道一覧の絞り込み・並び替え、制覇マップ、日本のタイル地図、アカウント削除、データの書き出し

## 7. データモデル（考え方の段階。物理設計はCTO / code-architect）

### 7.1 設計方針

1. **持ち主を記録する**: すべての行に `user_id` を持たせる。RLS（データベースの行ごとに、誰が読み書きできるかを決める仕組み）は、全テーブルで**本人だけが読み書きできる**ように設定する。
2. **公開範囲の列を先に用意する**: `roads` と `drives` に `visibility` を置き、既定値を `'private'` にする。MVPでは `'private'` 以外を保存できない制約をつける。将来 `'public'` を足すときに、データの移し替えが要らないようにするため。
3. **事実と主観を分ける**: 将来の共有で、事実と主観を別々に公開・名寄せできるようにする。
   - 道の事実（`roads`、`road_info_observations`）: 名称・都道府県・種別・ピン・通行ルール・施設
   - ユーザーの主観（`drives`、`photos`）: 評価・メモ・写真
4. **道の記録に個人情報を入れない**: `roads` には自由に書けるメモ欄を置かない。`road_info_observations.memo` は自由に書けるので、公開するときはモデレーションの対象にする。
5. **扱わないデータは列として作らない**: 速度・時刻・所要時間・タイム・傾き角・順位の列は、**どのテーブルにも作らない**。

| user_id | uuid | 必須 |

### 7.3 ストレージとセキュリティ

- 写真を置くバケット（Storage）は**非公開**にする。画像は署名付きURL（期限つきの一時的なURL）で表示する。
- Storageのポリシー: パスの1階層目が `auth.uid()` と一致するときだけ、読み書き・削除を許す。
- DBのCASCADEでは、Storage上のファイルまでは消えない。そのため、道や記録を削除するServer Actionの中で、対象のファイルも明示的に消す。

## 8. ユーザーストーリーと受入条件

共通の前提:
- 日付の判定は**日本時間（Asia/Tokyo）**で行う。表示は YYYY-MM-DD（道詳細の走行記録の見出しだけは「2026年9月14日（日）」の形でもよい）。
- 入力のチェックは、画面とサーバーの両方で行う。保存中はボタンを押せなくして、二重送信を防ぐ。

### US-01 マジックリンクでログインする（S1）
ユーザーとして、メールアドレスだけでログインしたい。パスワードを覚えずに、自分の記録を自分だけが見られる状態で使うため。

- [ ] Given 未ログイン When 保護されたページを開く Then `/login?next=…` に移動し、ログインした後は元のページに戻る。
- [ ] Given next=https://evil.example When ログインする Then `/roads` に移動する。
- [ ] Given `/login` When 形式の正しくないメールアドレスで送信する Then 「メールアドレスの形式が正しくありません」と表示し、メールは送らない。
- [ ] Given 正しいメールアドレス When 送信する Then `/login/sent` に移り、「○○にログイン用のリンクを送りました。このブラウザでリンクを開いてください。」と表示する。登録済みのアドレスかどうかで表示を変えない。
- [ ] Given 送信した直後 When 60秒以内 Then 再送ボタンは押せず、「あと○秒で再送できます」と表示する。
- [ ] Given 有効なリンク When 押す Then ログインした状態になる（初めての人には profiles の行を作る）。
- [ ] Given 期限切れ・使用済みのリンク When 押す Then `/login/error` に「ログインリンクの有効期限が切れているか、すでに使われています。もう一度メールアドレスを入力してください。」と表示し、ログイン状態にはしない。
- [ ] Given 送信回数の制限に当たった、または送信エラー When 送信する Then 「時間をおいてもう一度お試しください」と表示し、入力したアドレスは残す。

### US-02 ログアウトする（S1）
- [ ] Given ログイン中 When 設定画面の「ログアウト」を押す Then セッションを消して `/login` に移動する。
- [ ] Given ログアウトした後 When ブラウザの「戻る」で保護されたページに戻る Then 内容は表示せず、`/login` に移動する。

### US-03 他人の記録から切り離される（S1）

### US-04 道を登録する（S1）
ユーザーとして、走った道を名称と地図上のピンで登録したい。後から場所を思い出せるようにするため。

**操作の流れ**: 「道を登録」→ 名称・都道府県・種別を入力 → 開始ピンの「地図で選ぶ」を押す → フォームの中で全画面のピッカーが開く（URLは変わらない）→ 地図を動かして、画面中央の十字を道の上に合わせる → 「この位置にする」でフォームに戻り、ピンが表示される → 必要なら終了ピンも同じように置く → 保存 → 道詳細へ。
- 「キャンセル」やブラウザの「戻る」では、位置を変えずにフォームへ戻る。入力した内容は残す。
- 地図を最初に開いたときの中心は、置き済みのピン → 選んだ都道府県 → 日本全体、の順で決める。
- キーボードの矢印キーでも地図を動かせる。
- 現在地へ移動する機能はない。

- [ ] 必須項目: 名称（前後の空白を除いて1〜50文字）、都道府県（47から選ぶ）、開始ピン。任意項目: 終了ピン、種別（既定は「その他」）。道にはメモ欄がない。
- [ ] 種別の選択肢は **峠 / スカイライン / 海岸線 / 林道 / その他** の5つだけで、この順に並べる。
- [ ] Given 名称が空白だけ When 保存する Then 「道の名前を入力してください」と表示する。
- [ ] Given 名称が51文字 When 保存する Then 「50文字以内で入力してください」と表示する（50文字なら保存できる）。
- [ ] Given 都道府県を選んでいない When 保存する Then 「都道府県を選んでください」と表示する。
- [ ] Given 開始ピンがない When 保存する Then 「地図を動かして開始地点のピンを置いてください」と表示する。
- [ ] Given 正しい入力 When 保存する Then 道詳細に移動し、道一覧にも表示される。
- [ ] 地図のそばに「ピンは道の上に置いてください。自宅など、道以外の場所には置かないでください。」を常に表示する。

### US-11 走った道のコレクションを見る（S2）

  1. 「走った道 ○本」
  2. 種別ごとの本数（5種別とも、0本でも表示する）
  3. 「走った都道府県 ○/47」と進み具合のバー（読み上げでも同じ値を伝える）

**受入条件**

  - 走っていない県: 「— まだ」

### US-13 安全についての注意を受ける（S1。S3で仕上げ）

## 11. 評価軸（確定）

### A. 走ったときの評価（主観。走行記録ごと）
| 軸 | 形式 | 各値の言葉（1〜5） |
|---|---|---|
| 総合 | 1〜5（必須） | いまひとつ / やや物足りない / ふつう / 良い / とても良い |
| 景観 | 1〜5 | 同上 |

| 走りやすさ（道幅・見通し） | 1〜5 | 走りにくい / やや走りにくい / ふつう / 走りやすい / とても走りやすい |
| 交通量 | 少 / 普通 / 多 | 良い悪いではなく、状況の記録 |

### B. 道の情報（事実。変わることがあるので確認日を付ける）
US-10の表のとおり（通行ルール4項目・施設4項目）。

### 扱わないデータとその理由
**扱わないもの**: 速度、時刻・所要時間、区間タイム・ラップタイム、傾き角、ランキング、カーブの形からの自動採点、「攻めがい」「ワインディング度」など。

**理由**:
- Strava（運動記録アプリ）では、自動車やバイクの記録が区間タイムのランキングに混ざり、まとめて削除されたことがある。出典: https://the5krunner.com/2025/05/21/strava-removed-cars-leaderboard
  - 本アプリにはタイムやランキングの仕組みがないので、この種の問題は仕組みの上で起こらない。
  - ただし、この記事は「タイム計測が危険運転につながる」とは書いていない。本PRDもそうは主張しない。
- calimoto は、カーブの形から道の「楽しさ」を自動で点数にし（Calimeter）、傾き角も記録する（CSO分析 4章）。本アプリはこの方向を取らない。

## 12. 非機能要件

- **画面幅**: 360pxから使えることを保証する。320pxで横スクロールが出ないことはS3の目標とする。
  - 768px未満: 1カラムと、画面下のタブ（道 / コレクション / 設定）
  - 768px以上: 道一覧はリストと地図を左右に並べ、道詳細は2カラムにする
  - 1024px以上: 下のタブの代わりに、左のサイドナビ（幅240px）を出す
- **性能**: LCPは2.5秒以内（4G想定）。
- **アクセシビリティ（WCAG 2.1 AA を目標）**:
  - タップできる領域は44×44px以上にする。これは自社ルールで、AAより厳しい（WCAG 2.1のSC 2.5.5は、AAAの基準）。
  - 色だけで状態を伝えない（評価・古い情報の警告・コレクションの「走った/まだ」・開始/終了ピンには、文字や記号も付ける）。
  - 地図と同じ情報を、必ずリストでも出す。
  - 評価の入力:
    - 軸ごとに1つの `radiogroup` にし、軸の名前をラベルにする。
    - 各マスの読み上げ名は「4、良い」の形にする。
    - キーボード操作は WAI-ARIA APG のラジオグループに従う（矢印キーで動かすと、そのマスが選ばれる）。
  - 交通量は3択のラジオグループにして、「選択を解除」を付ける。
  - モーダル・全画面ピッカーは、表示中のフォーカスを中に閉じ込める。閉じたら、開く前の位置に戻す。
- **セキュリティ**:
  - 全テーブルで Supabase RLS を設定する。
  - Storageは非公開にし、画像は署名付きURLで表示する。
  - 入力のチェックはサーバー側でも必ず行う。
  - ログイン後に戻るページ（next）は、自分のサイトの中のパスだけを許す。
- **プライバシー**:
  - 既定で非公開にする。
  - GPSの走行軌跡は取らない。
  - 位置情報の取得（Geolocation API）は使わない。
  - 写真のEXIFは削除する。
- **地図**: Leaflet と国土地理院の地理院タイル（淡色地図）を推奨する。出典の表示は必須（https://maps.gsi.go.jp/development/ichiran.html ）。OSMの標準タイルは、利用ポリシーで大量の利用が制限されている（https://operations.osmfoundation.org/policies/tiles/ ）。最終決定はCTO。
- **技術スタック**: Next.js（App Router）、TypeScript、Tailwind CSS v4、Supabase、Vitest、Playwright、Vercel、pnpm。

## 13. 安全・法令への配慮

- **運転中のスマートフォンの使用**: 道路交通法で罰せられる行為で、令和元年（2019年）12月1日の改正で罰則が強くなった。警察庁が出している内容は次のとおり（出典: 警察庁 https://www.npa.go.jp/bureau/traffic/keitai/info.html ）。
  - 手に持って使う場合: 6月以下の拘禁刑または10万円以下の罰金、基礎点数3点、反則金は普通車18,000円・二輪車15,000円
  - 交通の危険を生じさせた場合: 1年以下の拘禁刑または30万円以下の罰金、基礎点数6点
  - → このアプリは「ドライブの後に記録する」ことを前提にし、リアルタイムの機能を持たない。
- **共同危険行為**: 道路交通法 第68条は、共同危険行為（2台以上で連なって危険な走り方をすること）などを禁止している（出典: e-Gov https://laws.e-gov.go.jp/law/335AC0000000105 ）。違反点数は25点で、仲間同士のツーリングでも対象になりうる（CSO分析 7章 https://www.webcartop.jp/?p=1234253 ）。
  - → タイム計測・ランキング・集団走行の呼びかけは扱わない。
- **アプリの審査**: Appleの審査ガイドライン1.4.4は、危険な運転をあおるアプリを禁止している（https://developer.apple.com/app-store/review/guidelines/ ）。将来アプリストアに出すことも考え、速度を扱わない方針を守る。
- **規制情報の扱い**: 二輪の通行止めは全国に約450か所あるとされる（https://young-machine.com/2019/06/18/37184/ ）。夜間通行止めの道もある（例: 奥多摩周遊道路 https://tabi-mag.jp/tk1370/ ）。
  - → アプリでは、規制情報を断定して表示しない。ユーザーの記録として扱い、公式情報を確かめるよう促す。
- **林道**: 選んだときに注意を出し、通行止めの道に入らないよう促す（US-05）。
- **公開共有を入れるとき**: コンテンツポリシー・通報機能・モデレーションがそろっていることを前提にする。

## 15. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| HEICに対応しないこと | iPhoneの写真がそのまま付けられず、記録が減る | 分かりやすい案内文を出す。S2で実機の動きを確かめ、MVPの後で対応するかを決める |
| 道の情報が古くなる | 間違った計画を立てる、信用が落ちる | 確認日を項目ごとに表示し、366日以上前なら警告する。公式情報ではないことを常に注記する |
| ピンを自宅に置かれる | 公開したときに、自宅の場所が漏れる | 補足の文で注意する。公開機能ではぼかしの処理を入れる |
| 3週間という短い日程 | リリースが遅れる | S1をいちばん薄い縦切りにする。S2の地図とコレクションは後ろに回せるようにしておく |
| マジックリンクのメールが届かない、送信回数の制限 | ログインできない | CTOがメール送信の設定を確かめる |
| ログインリンクを、送信したのと別のブラウザで開く（アプリ内ブラウザなど） | PKCE（ログインを始めたブラウザでしか完了できない仕組み）の照合に失敗し、ログインできない | /login/sent に「このブラウザでリンクを開いてください」と出す。失敗したら /login/error で案内する。S2で実機確認する |
| メールアプリの事前チェック（スキャナー）がリンクを先に開く | リンクが使用済みになり、ログインに失敗する | /login/error で送り直しを案内する。S2で起きるかを確かめる |
| 地図タイルの利用条件 | 出典の表示漏れ、利用の制限 | 地理院タイルを使い、出典の表示を受入条件に入れる |
| 速度などを連想させる表現が紛れ込む | 方針に反する、評判の危険 | 禁止語の自動チェック（US-14） |
| Storageにファイルが残る | 容量のコスト、消したはずのデータが残る | 削除の処理で、ファイルも明示的に消す |
