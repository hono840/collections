## 1. 新しい前提（2026-10-08 のプロダクト制約）

- ログインなし。データはこの端末（ブラウザ）の中だけに保存。JSON で書き出し・読み込み。
- 写真なし。地図は地理院タイル。
- 画面: ホーム／道の登録・編集／道の詳細／走った記録の追加・編集／データ／はじめての案内（3ステップ以内、安全の注意を含む）。
- 速度・タイムを示す UI は作らない。レースを思わせる見た目も使わない（v1 1章の Don't を引き継ぐ）。

## 2. デザイン原則（4つだけ）

1. **1画面 = 1つの仕事。** ホームは「道を選ぶ」、詳細は「道を見返す」、フォームは「書く」。その画面の仕事に関係ない物は置かない。
2. **主な操作は、いつも画面の一番下に、文字つきで1つ。** 「＋ 道を登録」「＋ 走った記録を追加」「保存」。親指が届く場所で、位置が変わらないので覚えなくてよい。
3. **色には意味がある。** 鮮やかな色は「道の種類」と「主な操作（青）」だけに使う。飾りのための色は使わない。**色だけで伝えない**: 種類は必ず「記号＋名前」、評価は必ず「数字＋言葉」と一緒。
4. **外で読める。** 本文・補足ともに 7:1 前後を目標（最低 4.5:1）。押せる物は 44px 以上。文字は 13px 未満にしない。

### 記憶に残る一点
**「道の色」。** 5種類の道にそれぞれ鮮やかな色を割り当て、道の詳細の一番上を、その色でベタ塗りした帯（白い記号と白い道の名前）にする。日本の道路の案内標識（青地に白文字）のように、色の面に白い文字を置く。ホームでは、走った道の本数を種類の色で塗り分けた1本の「色の帯」で見せる。ほかの部分（地・カード・文字）は白と墨で静かに抑える。

### やめるもの（v1 から削除）
- 明朝体・等高線の模様・紙の地色（見づらさの原因。飾りでしかない）
- 下のタブバー・左のサイドナビ・コレクション専用の画面（ホームに統合）
- 写真・ログイン関連の画面と部品
- 「終了地点」のピン（場所は1点だけにする。**CPO 確認事項**。7-2 参照）

### 引き継ぐもの（v1 から残す）
- 評価に星や信号色を使わない。評価の色は青1色、数字と言葉を必ず添える
- 交通量に良い・悪いの色を付けない
- 安全の注意は警告色で強く出さない（お知らせとして落ち着いて出す）
- 地理院タイルの淡色地図と出典表示（v1 6章）

## 3. ナビゲーションの決定: 「シンプルな上のバー ＋ 下の主ボタン」（タブバーは使わない）

**決定**: 画面上に高さ56pxの上のバー、画面下に「主ボタンのバー」（BottomActionBar）を置く。下のタブバーは作らない。

**理由**:
1. **行き先が2つしかない。** 上の段で並ぶ画面は「ホーム」と「データ」だけ（詳細とフォームはホームの下の階層）。Material Design 3 はナビゲーションバーを 3〜5 個の行き先向けとしている（出典1）。NN/g も、タブバーは「行き先が比較的少ないサイト」向けで、5を超えると収まらないとする（出典3）。2つのためにタブを常時出すと、画面の下という一番押しやすい場所を、めったに使わない「データ」に取られる。
2. **下の一番良い場所は「主な操作」に使う。** 片手持ちが 49%、両手で支えて片手で押すのが 36%（Hoober の 1,333人の観察、出典5）。親指が届きやすい画面の下に、その画面で一番大事な操作を置く。Material は FAB（画面に浮かぶ主ボタン）を「その画面の主な操作」とし、1画面に1つ、文字つきの「拡張FAB」も認めている（出典2）。
3. **丸い「＋」だけのボタンにしない。** CEO の「一見使い方がわからない」への答えとして、記号だけでなく必ず文字を付ける。そのため丸い FAB ではなく、**画面幅いっぱいの文字つきボタン**にする（拡張FAB の考え方を、押し間違えにくい形にしたもの）。
4. **「データ」はホームの上のバーの右に、記号＋文字で置く**（「データ」）。使う頻度は低いが、見つからないと困る（バックアップ）。

**v1/UX との違い**: UX 2.1 は「画面中央に浮かぶ追加ボタンは作らない（その場ですぐ記録する印象を避けるため）」としていた。v2 の下の主ボタンは「道を登録」「走った記録を追加」で、現在地も時刻も使わない。安全バナー（6-8）と初回の注意（6-10）で「走った後に書く」ことを伝える方針は変えない。

### 4-2. 道の種類の色（必ず記号＋名前と一緒に使う）

| 種類 | 記号（v1 の形を継続） | solid（ライト・ダーク共通） | tint ライト | bright（ダークの記号用） | tint ダーク |
|---|---|---|---|---|---|
| 峠 | 背中合わせの弧「)(」 | #C2410C（橙） | #FFEDD5 | #FB923C | #3A2414 |
| スカイライン | 山形の折れ線と上の1本線 | #7C3AED（すみれ） | #EDE9FE | #B794F6 | #2C2346 |
| 海岸線 | 直線と下の波線2本 | #0F766E（青緑） | #CCFBF1 | #2DD4BF | #0F3330 |
| 林道 | 針葉樹 | #3F7D20（緑） | #E3F1D4 | #86C95A | #1F3318 |
| その他 | 中心に点のある輪 | #5B6472（灰） | #E8EBEF | #A9B3BF | #262D36 |

**使い方の決まり**
- **solid**: 白い文字・白い記号を上に置く「面」に使う（詳細の帯、選択中のチップ、種類タイル選択中、地図のピン）。ダークでも solid は同じ値（面の上の白文字のコントラストはモードに関係なく保たれる）。
- **tint**: 未選択のチップ・カードの記号の箱の地。上の文字は ink、記号は solid（ライト）／bright（ダーク）。
- 種類の色を、地（bg/surface）の上の**文字の色**には使わない（ライトでは計算上 4.5:1 を超えるが、色の意味が「文字の強調」と混ざるため）。
- 青（primary）は「操作」の色なので、種類の色に青を使わない（海岸線は青緑、スカイラインはすみれで分けた）。
- 色の見え方が違う人への配慮: 海岸線（青緑）と林道（緑）は似て見えることがある。**記号の形と名前で必ず区別**し、実装後に Chrome DevTools の色覚シミュレーション（4条件）で、記号と名前だけで区別できることを確かめる。

### 4-4. 文字

**書体は1つ: BIZ UDPGothic（400 / 700）。** 明朝と等幅版（BIZ UDGothic）は読み込みをやめる。
- 理由: 屋外・小さな画面での読みやすさを最優先。ユニバーサルデザイン書体で、太字がはっきりしている。書体を減らすと日本語フォントの読み込みも軽くなる。個性は書体ではなく「道の色」で出す。
- 数字（評価・本数・日付）は `font-variant-numeric: tabular-nums`（桁がそろう）。
- 代わりの書体: "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", Meiryo, sans-serif

**文字サイズ（スマホ基準。1画面で主に使うのは3段階まで — NN/g 出典4）**
| トークン | サイズ / 行の高さ / 太さ | 用途 |

| text-number | 40 / 1.1 / 700 | ホームの「走った道 12本」の数字 |
| text-title | 20 / 1.4 / 700 | 上のバーの画面名・フォームの画面名 |
| text-heading | 18 / 1.45 / 700 | セクションの見出し（「走った記録」など） |
| text-card | 17 / 1.4 / 700 | カードの道の名前 |

### 4-5. 余白・サイズ（4px 単位）

- 段階: 4 / 8 / 12 / 16 / 24 / 32 / 48
- 画面の左右: 16px（スマホ）／24px（768px以上）
- セクションの間: 24px（スマホ）／32px（768px以上）。カードとカードの間: 12px。
- **押せる物の大きさ: 44×44px 以上**（WCAG 2.2 の AA は 24px — 出典6。重要な操作は 44px の 2.5.5（AAA）をすすめている）。主ボタン 56px、評価マス 56px。
- 上のバー: 56px（＋ safe-area の上）。下の主ボタンのバー: 上下 12px ＋ ボタン 56px ＋ safe-area の下 = 80px＋α。
- 画面の中身の下に、下のバーの高さ分の余白を必ず空ける（最後のカードが隠れないように）。

### 4-6. 角の丸み・影・線

| トークン | 値 | 用途 |
|---|---|---|
| radius-sm | 8px | 入力欄・評価マス・小さなボタン |
| radius-md | 12px | 主ボタン・カード・お知らせ |
| radius-lg | 20px | シートの上の角・詳細の帯の下の角（768px以上のみ） |
| radius-full | 9999px | チップ・バッジ |

- 影は2つだけ:
  - shadow-bar（上下のバー・下から出るシート）: ライト `0 -1px 0 #DDE1E7, 0 -4px 16px rgba(21,32,43,0.08)`（下のバー）／上のバーは下側に1px line のみ。ダーク: 1px line のみ（影なし）。
  - shadow-sheet（シート・ダイアログ）: ライト `0 -8px 32px rgba(21,32,43,0.18)`／ダーク `0 -8px 32px rgba(0,0,0,0.5)`
- カードは影なし、1px line の枠だけ（同じ影を全カードに付けない）。
- 線: 1px（区切り・枠）、2px（フォーカス・エラー・選択中の枠）。

### 4-7. 動き

| トークン | 値 | 用途 |
|---|---|---|
| duration-press | 100ms | 押した瞬間の色 |
| duration-base | 200ms | シート・トースト・開閉 |
| duration-reveal | 600ms | ホームの「色の帯」が左から伸びる（1回だけ） |
| ease-standard | cubic-bezier(0.2, 0, 0, 1) | 共通 |

- **見せ場は1つだけ**: ホームを開いたとき（そのタブで1回だけ）、色の帯が左から伸びる。カードが次々に現れる動き・ホバーで浮く動き・バウンス・横に流れる動きは使わない。
- 操作への返事の動きは使ってよい: 評価マスを押すと塗りが 100ms で変わる／シートが下から 200ms で出る／保存後のトーストが下から 8px＋フェード。
- `prefers-reduced-motion: reduce` のとき: 全ての時間を 0.01ms に。色の帯は最初から伸びた状態、シートはフェードだけ、地図のなめらかな移動（flyTo）は即時移動にする。

## 5. 画面ごとのワイヤーフレーム（幅 390px）

記号の読み方: `[ ]` ボタン・入力欄／`▓` 種類の色の面／`▮▯` 評価メーター／`›` 移動できる行。

### 5-1. はじめての案内（2ステップ。初回だけ）

## 6. 部品の仕様

共通:
- キーボード操作の枠: `:focus-visible` のときだけ、2px の focus 色を外側に 2px 離して付ける。種類の solid の上（帯の中・選択中チップ）では白い 2px の枠＋外側に ink 1px にする。
- ホバーは `@media (hover: hover)` の中だけ。
- 固定の上下のバーがフォーカスを隠さないよう、`scroll-padding-top: 72px; scroll-padding-bottom: 96px`（＋safe-area）を html に付ける（WCAG 2.2 の 2.4.11 — 出典8）。

### 6-1. 上のバー（TopBar）
- 高さ 56px＋safe-area、surface の地、下に 1px line。
- 左: ホームではアプリ名（text-title）。下の階層では「‹ ホーム」「‹ もどる」（記号＋文字、44px、primary の文字）。フォームでは「キャンセル」（同じ）。
- 中央: 画面名（text-title、1行で省略）。ホームでは置かない。
- 右: ホームでは「⇅ データ」、詳細では「… その他」（記号＋文字。幅が足りないときは記号のみにして `aria-label`）。
- スクロールしても上に固定。大きなタイトルが縮む動きは付けない（簡単さを優先）。

### 6-2. 下の主ボタンのバー（BottomActionBar）
- 画面の下に固定。surface の地、shadow-bar、上下 12px・左右 16px、下に safe-area。
- 中のボタン: primary、高さ 56px、幅いっぱい、radius-md、文字 text-body 700、先頭に記号（＋や✓）。
- 状態:
  | 状態 | 見た目 |
  |---|---|
  | 通常 | primary の地、on-primary の文字 |
  | 押した瞬間 | primary-pressed（100ms） |
  | フォーカス | 2px focus 枠（外側2px） |
  | 保存中 | 文字を「保存中…」に変え、左に小さな回転記号、`aria-busy="true"`。幅は変えない |
  | 押せない | 使わない。フォームは押せる状態のまま、押したらエラーを出して最初のエラー欄へフォーカス（押せない理由が分からなくなるのを防ぐ） |
- キーボードが出ている間（入力中）は、バーを隠さず、キーボードの上に乗る（`interactive-widget=resizes-content` などの実装方法は frontend が決める）。隠れる場合は、フォームの最後にも同じボタンを置く。

### 6-3. ボタン（そのほか）
| 種類 | 高さ | 見た目 |
|---|---|---|
| primary | 52px（バー内は56） | primary の地、白文字 700 |
| secondary | 52px | surface の地、1px line-strong、ink 文字 700。押した瞬間 bg |
| text（文字ボタン） | 44px（文字は見た目上小さくても押せる範囲は44） | 地なし、primary の文字 700。危険な操作は danger の文字＋記号 |
| danger | 52px | danger の地、on-danger 文字 700 |
- 文字は「すること」にする（「道を登録」「記録を保存」「書き出す」「削除する」）。末尾の「→」は付けない。

### 6-4. 道のカード（RoadCard）
- surface の地、1px line、radius-md、余白 12px（左の箱）／16px（右）。影なし。カード全体が1つのリンク（高さ 88px 以上）。
- 中身:
  1. 左: 種類の箱 48×48、radius-sm、**solid の地に白い記号 28px**（カードの色の手がかり。ダークも同じ）。
  2. 右上: 道の名前（text-card、ink、2行まで）、右端に「›」（ink-muted）。
  3. 2行目: 都道府県（text-small ink-muted）と種類バッジ（6-6）。間 12px。
  4. 3行目: 評価メーター（小）＋平均（text-body 700、tabular-nums、例 4.3）、16px あけて「3回走った」（text-small ink-muted）。記録0件なら「まだ記録がありません」（text-small ink-muted）だけ。
- 状態: 押した瞬間 = bg の地。ホバー = 枠を line-strong。フォーカス = カード全体に focus 枠。浮き上がり・拡大はしない。
- 読み上げ: 「碓氷峠、群馬県、峠、総合評価 平均4.3、3回走った」。

### 6-5. 種類チップ（TypeChip、ホームの絞り込み）
- 高さ 40px（上下に 2px の余白を足して押せる範囲 44px）、左右 12px、radius-full、間 8px、折り返す。
- 中身: 記号 18px＋種類名 text-small 700＋本数（tabular-nums）。
| 状態 | 見た目 |
|---|---|
| 未選択 | tint の地、記号は solid（ダークは bright）、文字 ink |
| 選択中 | solid の地、先頭に白いチェック記号、記号と文字は白 |
| 0本 | 出す（隠さない）。文字は ink-muted、押せる |
| 「すべて」未選択 | surface の地、1px line-strong、ink 文字 |
| 「すべて」選択中 | ink の地、bg 色の文字＋チェック |
- `button` に `aria-pressed`。同時に選べるのは1つ（選ぶと他は解除）。

### 6-6. 種類バッジ（TypeBadge、表示だけ）
- 高さ 24px、左右 8px/10px、radius-full、tint の地、記号 14px（solid/bright）＋名前 text-caption 700（ink）。

### 6-7. 評価の入力（RatingInput、5マス）
- 星は使わない。5つのマスを横に並べ、`role="radiogroup"`（各マス `role="radio"`、読み上げ名「4、良い」）。キーボードは WAI-ARIA APG のラジオグループ（現在の実装 `RatingInput.tsx` の方式を継続）。
- **大きさ: 各マスは高さ 56px、幅は5等分（flex-1、最小 52px）、間 8px。** 360px 幅では 328px に収まる（52×5＋8×4＝292〜）。390px では 1マス約 65px。親指で押し分けやすい。
| 状態 | 見た目 |
|---|---|
| 未選択 | surface の地、1px line-strong、数字 text-heading 700 ink-muted |
| 値Nを選択 | 1〜N は primary の地に白の数字、N のマスだけ外側に 2px ink 枠と下に 4px の ink の目印（形でも分かる） |
| 押した瞬間 | 押したマスを primary-tint（100ms） |
| フォーカス | focus 枠 |
| エラー（総合が未選択） | 全マスの枠を 2px danger、下に「! 総合評価を選んでください」（danger text-small） |
- 下に両端の言葉（text-caption ink-muted）と「選んだ評価: 4（良い）」（text-small ink、`aria-live="polite"`）。
- 任意の軸は、選んだ後だけ右上に「選択を解除」（text ボタン 44px）。
- 各値の言葉は v1 4-2 のものを使う（総合・景観／路面状態／走りやすさ）。
- **表示だけのメーター（RatingMeter）**: マスはカード用 14×8px・間 3px、詳細用 20×10px・間 4px、radius 2px。塗りは primary、空は 1px line-strong の枠。塗る数のルールは v1 4-2 と同じ（表示値を四捨五入）。必ず横に数字。`role="img"`、読み上げ名「総合評価 平均4.3」。

### 6-8. お知らせ（安全バナー・林道の注意）
- **SafetyBanner**（走った記録フォームの上。閉じない、`role="note"`）: primary-tint の地、radius-md、余白 12px/16px。左に「P」の角丸四角（20px、1.5px primary 枠、primary の文字）。見出し「運転中は操作しないでください。」（text-small 700 ink）、本文「停車してから、またはドライブの後に記録してください。」（text-small ink）。
- **ForestRoadNote**（林道の注意。登録で林道を選んだとき・詳細の帯の下・記録フォームの安全バナーの下）: caution-tint の地、radius-md、余白 12px/16px。先頭に林道の記号（caution-icon 色）と「注意」（text-small 700 ink）。本文は M-08（text-small ink）。閉じない。
- **書き出しの声かけ**（ホーム）: caution-tint、1行、右に「書き出す」（primary の文字ボタン）と「×」（44px、`aria-label="14日間かくす"`）。

### 6-9. 入力欄・選択
- 入力欄: 高さ 52px、surface の地、1px line-strong、radius-sm、文字 16px（iOS の自動拡大を防ぐ）。ラベルは欄の上 6px（text-small 700 ink）。必須は「必須」と文字で（ink-muted の枠付き小札）。
- フォーカス: 2px primary 枠（枠の太さが変わっても文字がずれないよう、通常時も 2px 分の余白を確保）。
- エラー: 2px danger 枠＋下に「! 〜」（danger text-small）。保存時のエラーは最初のエラー欄へフォーカス。
- 交通量（SegmentedControl）: 溝は bg の地＋1px line-strong、余白 2px、radius-sm。各選択肢 44px・等分・最大幅 320px。選択中 = surface の地＋2px ink 枠＋ink 700。3つとも同じ見た目（良い悪いの色なし）。丸の数の記号（1/2/3個）を添える。
- 都道府県: 端末標準の select（北から並べる）。

### 6-10. シート・ダイアログ・トースト
- **下から出るシート**（その他メニュー・削除確認・読み込み確認・離れる確認）: surface の地、上の角 radius-lg、shadow-sheet、最大高さ 85vh、後ろに scrim。中のボタンは縦に積み、52px、幅いっぱい。768px 以上は中央のダイアログ（最大幅 480px、radius-lg）。
- **削除の確認**: 見出し「この道を削除しますか？」／本文「走った記録○件と道の情報も削除されます。元に戻せません。」（○件は0でも出す）。ボタン: 上［削除する］danger、下［やめる］secondary。最初のフォーカスは［やめる］。`role="alertdialog"`。
- **トースト**: 下のバーの上 12px、左右 16px。ink の地（ダークは ink＝明るい地）に bg 色の文字 text-small、先頭に success の✓（ライトでは ink 地の上で見えるよう #4ADE80 を使う）。4秒で消える。`role="status"`。失敗は自動で消さず「再試行」付き、`role="alert"`。

### 6-11. 空の状態のイラスト
- 使う所: ホームの0本、はじめての案内ステップ1 の2か所だけ。小さな空状態（記録0件、絞り込み0件など）は文字だけ。
- 図柄: ゆるやかな2〜3つの丘（line 色の面、角のない形）の上を、**1本の道が5色に色を変えながら**うねって奥へ続く（5種類の solid を順に、太さ 6px、端は丸）。地平線に小さな太陽か雲1つまで。
- 描かない物: 人・車・バイク・矢印・速度を思わせる線・旗。
- 形式: インライン SVG、200×140、6KB 以下、`aria-hidden="true"`。ダークでは丘を #2C3540、道は bright 色に。
- NN/g の空状態の3つの役割（いまの状態を伝える／使い方を教える／次の操作への道を示す — 出典9）を、見出し・説明文・下の主ボタンで満たす。

### 6-12. 地図
- タイル: 地理院タイル 淡色地図 `https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png`（v1 6-1 を継続）。淡い地図の上で、種類の solid 色のピンがはっきり見える。
- ピン: しずく形 32×40、種類の solid で塗り、白い記号 16px、2px 白の縁＋外側 1px rgba(21,32,43,0.45)。ピンは1つだけ（終了地点のピンは作らない）。
- 出典「地理院タイル」: 右下、text-caption、ink、surface 不透明度 0.85 の地。上下のバーやシートで隠さない。
- ダーク: タイルにだけ `filter: brightness(0.82) saturate(0.85)`（v1 6-3 を継続）。
- 詳細の地図は表示だけ（指で動かさない、`aria-hidden`。代わりに「地図アプリで開く」と県名を文字で出す）。動かせる地図は「場所を選ぶ」画面だけ。
