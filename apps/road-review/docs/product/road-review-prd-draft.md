# 公道レビュー（road-review）PRD ドラフト v2

- ステータス: ドラフト（CEO承認待ち）
- 作成: CPO（feature-planner / ux-researcher 委譲、1イテレーション済み）
- 保存先: apps/road-review/docs/product/road-review-prd-draft.md

## 1. 概要
「公道レビュー」は、自分が実際に走った峠・スカイライン・景観道路などの公道を個人の「道コレクション」として記録し、ドライブ後に景観・路面・走りやすさ・交通量などの観点で振り返れる個人向けWebアプリ。MVPは非公開の個人記録に特化する。速度・タイム・ランキングなど、危険運転を誘発しうる要素は一切扱わない。

## 2. 課題
- 走った道の記憶が写真フォルダ・SNS・メモに散らばり、「あの峠はどうだったか」を後から振り返りにくい。
- 既存のツーリング系アプリ（NAVITIME ツーリングサポーター、Calimoto、REVER、Kurviger 等）はルート計画・GPSログ記録が中心で、「道そのもの」の印象や実用情報を自分用に蓄積する用途には向いていない。
- 冬季閉鎖・料金・トイレの有無など、次回の計画に役立つ情報が手元に残らない。

参考モデル: AllTrails の「登録済みの道（トレイル）＋日付付きの複数レポート（状態タグ）」という構造が本アプリに最も近い。

## 3. ターゲット / ペルソナ（仮説ペルソナ・未検証）
- **P1: 景色ドライブ派の会社員（30代・四輪）** 週末に景観道路を走るのが趣味。走った道を地図で眺め、季節ごとの違いを残したい。
- **P2: ツーリングライダー（40代・二輪）** 季節ごとに峠を巡る。路面の荒れ・冬季閉鎖・トイレ/駐車場の有無を次回のために残したい。
- 共通: ドライブ中は操作せず、帰宅後や休憩中（安全な場所に停車中）に落ち着いて記録したい。

## 4. MVPスコープ
| # | 機能 | 内容 |
|---|---|---|
| 1 | ログイン | Supabase Auth（方式は未決事項。推奨: メールマジックリンク） |
| 2 | 道の登録 | 名称・都道府県・種別（峠/スカイライン/その他）・地図上の開始/終了ピン（手動配置） |
| 3 | 走行記録の登録 | 走行日・車両種別・天候・主観評価・メモ |
| 4 | 道の情報 | 冬季閉鎖・料金・規制・施設を確認日付きで記録 |
| 5 | 写真添付 | 1記録あたり最大5枚、クライアント側リサイズ、EXIF（GPS含む）削除 |
| 6 | 道一覧 | 地図表示 + リスト表示、空状態 |
| 7 | 道詳細 | 走行記録を新しい順に表示、最新の道の情報を表示 |
| 8 | 安全注意表示 | 初回利用時・記録フォームでの注意表示 |
| 9 | 編集・削除 | 道/記録の編集・削除（道の削除は記録・写真も連鎖削除） |

MVPに含めないもの: リアルタイムGPS追跡・現在地追従、走行中の操作を前提とした機能、公開共有。

## 5. 将来スコープ
- 公開共有・他ユーザーのレビュー閲覧（コンテンツポリシーとモデレーションが前提）
- GPXインポート / 地図上のポリライン描画（自宅周辺の始点・終点を自動でぼかす処理が前提）
- 振り返り機能（都道府県別の制覇マップ、季節別アルバム）
- 道路マスタの全ユーザー共有化
- 冬季閉鎖など公式情報へのリンク集（機械可読な公開データは調査で見つからなかったため、まずはリンク）

## 6. ユーザーストーリー
- **US-01** ユーザーとして、ログインしたい。自分の記録を自分だけが見られる状態で保存するため。
- **US-02** ユーザーとして、走った道を名称と地図上のピンで登録したい。後から場所を思い出せるようにするため。
- **US-03** ユーザーとして、ドライブ後に走行日・主観評価・メモを記録したい。その日の印象を残すため。
- **US-04** ユーザーとして、冬季閉鎖・料金・規制・施設といった道の情報を確認日付きで残したい。次に行く計画に役立てるため。
- **US-05** ユーザーとして、走行記録に写真を添付したい。景色を振り返るため（位置情報は外したい）。
- **US-06** ユーザーとして、自分の道を地図とリストで一覧したい。コレクションを眺めるため。
- **US-07** ユーザーとして、道ごとの過去の記録と最新の道の情報を見たい。季節や年ごとの違いを比べるため。
- **US-08** ユーザーとして、運転中に操作しないよう注意を受けたい。安全に記録するため。
- **US-09** ユーザーとして、道・記録を編集・削除したい。誤りを直すため。

## 7. 受入条件（MVP分）

**US-01 ログイン**
- Given 未ログイン When 保護ページにアクセス Then ログイン画面へ遷移する。
- Given ログイン済みユーザーA When ユーザーBの道/記録/写真のURLに直接アクセス Then 404（または権限なし）となり、内容は表示されない。

**US-02 道の登録**
- 必須: 名称（1〜50文字）、都道府県（47から選択）、開始ピン。任意: 終了ピン、種別（既定「その他」）。
- Given 必須項目が未入力 When 保存 Then 該当項目にエラーが表示され保存されない。
- Given 正しい入力 When 保存 Then 道詳細に遷移し、一覧に表示される。

**US-03 走行記録**
- 必須: 走行日、総合評価。任意: 車両種別（四輪/二輪）、天候（晴/曇/雨/雪/その他）、各主観評価、メモ（2000文字以内）。
- Given 走行日に未来日付 When 保存 Then 「未来の日付は選べません」エラーが表示され保存されない。
- Given 評価が1〜5以外 When 保存 Then 保存されない（UIは1〜5のみ選択可能、サーバー側でも検証）。

**US-04 道の情報**
- 各項目は「あり/なし/不明」等の選択 + メモ + 確認日（既定: 走行日）。走行記録ごとに保存する（情報は時期で変わるため）。
- Given 道詳細 When 表示 Then 確認日が最も新しい情報が「確認日 YYYY-MM-DD・ユーザー記録」として表示され、「お出かけ前に道路管理者の公式情報を確認してください」の注記が表示される。

**US-05 写真**
- 形式: JPEG/PNG/WebP（HEICは未決）。最大5枚/記録、元ファイル1枚20MBまで。
- 長辺2048pxにクライアント側でリサイズしてからアップロードする。
- Given GPS付きJPEG When アップロードして保存 Then 保存後の画像からGPS情報を含むEXIFが検出されないこと。
- Given 5枚添付済み When 6枚目を選択 Then 「1記録につき5枚まで」と表示され追加されない。
- Given アップロード失敗 When 発生 Then エラーメッセージと再試行ボタンが表示され、入力済みの記録本文は失われない。

**US-06 一覧**
- Given 道0件 When 一覧を開く Then 空状態（「最初の道を登録しましょう」+ 登録ボタン）が表示される。
- Given 道1件以上 When 一覧を開く Then 地図にピン、リストに名称・都道府県・最終走行日・総合評価が表示される。

**US-07 道詳細**
- Given 記録が複数 When 道詳細を開く Then 走行日の新しい順に表示される。

**US-08 安全注意**
- Given 初回ログイン When トップ表示 Then 「運転中は操作しないでください。記録は安全な場所に停車後、またはドライブ後に」を表示し、「確認しました」で閉じる（以後再表示しない）。
- Given 記録フォーム When 表示 Then 同文言がフォーム上部に常時表示される。
- MVPにはリアルタイムGPS追跡・現在地追従の機能が存在しないこと。

**US-09 編集・削除**
- Given 自分の記録 When 編集して保存 Then 変更が道詳細に反映される。
- Given 道の削除 When 実行 Then 「この道の記録○件と写真○枚も削除されます」の確認ダイアログが表示され、確定後に記録・写真（Storage上のファイルを含む）も削除される。キャンセル時は何も削除されない。

## 8. レビュー評価軸案

**A. 走行時の評価（主観・走行記録ごと）**
| 軸 | 形式 | 備考 |
|---|---|---|
| 総合 | 1〜5（必須） | |
| 景観 | 1〜5 | |
| 路面状態 | 1〜5 | 荒れ・落石・落ち葉など |
| 走りやすさ（道幅・見通し） | 1〜5 | 安全にゆったり走れるかの観点。すれ違いのしやすさ、見通し |
| 交通量 | 少/普通/多 | 良し悪しではなく状況の記録（「空いている＝高評価」にしない） |

**B. 道の情報（事実・変わりうる／確認日付き）**
| 項目 | 形式 |
|---|---|
| 冬季閉鎖 | あり/なし/不明 + 期間メモ + 確認日 |
| 料金 | 有料/無料/不明 + 金額メモ + 確認日 |
| 二輪/時間帯規制 | メモ + 確認日 |
| 施設 | 駐車場/トイレ/道の駅/展望台（チェック） |

**扱わないデータ**: 速度、区間・ラップタイム、ランキング、「攻めがい」「ワインディング度」など、カーブや速度を求める評価。
（参考: Strava は危険と判断された区間（セグメント）のタイムランキングを外す仕組みを持つ — https://support.strava.com/hc/en-us/articles/216919507 ）

## 9. 非機能要件
- モバイルファースト（360px幅〜）。LCP 2.5秒以内（4G想定）。
- アクセシビリティ WCAG 2.1 AA: 評価入力はキーボード操作可能、色だけで状態を伝えない、地図と同じ情報を必ずリストでも提供する。
- セキュリティ: 全テーブルで Supabase RLS（本人のみ読み書き）、Storage バケットは非公開、画像表示は署名付きURL。
- プライバシー: 既定で非公開。GPS軌跡を取らないため自宅位置は記録されない。ピンはユーザーが道の上に手で置く。写真のEXIF（GPS含む）は削除する。
- 地図: Leaflet + 国土地理院 地理院タイル（出典表示必須 — https://maps.gsi.go.jp/development/ichiran.html ）を推奨。OSM標準タイルは利用ポリシーで大量利用が制限され、出典表示が必須（https://operations.osmfoundation.org/policies/tiles/ ）。最終決定はCTO。

## 10. 安全・法令配慮
- 運転中のスマートフォン等の使用は道路交通法の罰則対象で、令和元年（2019年）12月1日施行の改正で罰則が強化された。警察庁の掲載内容: 保持（通話・画面注視）は「6月以下の拘禁刑又は10万円以下の罰金」・基礎点数3点・反則金 普通車18,000円/二輪車15,000円、交通の危険を生じさせた場合は「1年以下の拘禁刑又は30万円以下の罰金」・基礎点数6点。
  出典: 警察庁 https://www.npa.go.jp/bureau/traffic/keitai/info.html
  → このためアプリは「ドライブ後に記録する」前提とし、リアルタイム機能は持たない（US-08）。
- 道路交通法 第68条（共同危険行為等の禁止）を踏まえ、集団で速度を競うことにつながる機能（タイム計測・ランキング・集団走行の呼びかけ）は扱わない。
  出典: e-Gov 法令検索 道路交通法 https://laws.e-gov.go.jp/law/335AC0000000105
- 道の情報はユーザー自身の記録であり公式情報ではないことを画面に表示し、道路管理者の公式情報の確認を促す。
- 一部の峠で二輪車の夜間通行規制があるという話はよく報じられるが、具体的な区間は今回確かめていない。アプリ側で規制情報を断定表示せず、ユーザーのメモ扱いとする。
- 公開共有を入れる際は、速度・レース、通行止め区間や私有地の走行をすすめる投稿を禁止するコンテンツポリシーとモデレーション（投稿の監視・削除）の仕組みを前提条件とする。
