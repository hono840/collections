用語メモ:
- **静的書き出し**（`output: 'export'`。サーバーで動く部分を持たず、HTML などのファイルだけを作って配る方式）
- **CSP**（ブラウザに「このページでは、どこから来たスクリプトを動かしてよいか」を伝える決まり）
- **IndexedDB / localStorage**（どちらもブラウザの中の保存場所。IndexedDB は大きなデータ向け、localStorage は小さな文字データ向け）
- **サービスワーカー**（電波がなくてもページを開けるように、ブラウザが部品を手元に取っておく仕組み）

## 0. 結論（先に）

1. **4つの文書は同じ方向を向いているが、細かい決まりが 30 か所以上くい違っている。** とくに大きいのは「初回の案内の枚数」「ピンの数と必須かどうか」「道の情報の持ち方」「タブの有無とコレクション画面」「書き出しのお知らせの日数」「下書きの戻し方」。実装の前に、この文書の 1章の決定を正とする。
2. **ARCH 13章の Supabase からのデータ移行 SQL は消す。** CEO は「古いデータは捨ててよい」と決めている（PRD:599-601）。
3. **技術の芯（静的書き出し・IndexedDB・JSON の書き出し/読み込み）は実現できる。** Next.js 16.3.6 の同梱 docs で制限を確かめた（2章）。ただし「ハッシュ CSP を後から HTML に入れる方式が Vercel で効くか」は**まだ誰も確かめていない**。Step 0 の試作で確かめるまで公開しない。
4. **MVP は広すぎる。** 22 のストーリーのうち、名前検索・読み込みの「合わせる」・コレクション専用画面・地図の一覧・オフライン起動・ダークモード・パソコン用の2列表示などを後ろへ回すと、作る量が大きく減り、データを守る機能（下書き・書き出し・読み込み）に力を集められる（2.6）。
5. 実装は 17 の段階に分け、各段階でテストを先に書き、スマホの画面写真（360×640 と 390×844）で確かめる（3章）。

### 2.2 Leaflet（地図）を静的書き出しで使う

- 【事実】今のコードは Leaflet を `useEffect` の中で `await import('leaflet')` している（ARCH:548）。ビルド時に `window` に触らないので、静的書き出しで問題ない。
- 【事実】Leaflet は部品の位置を `style` 属性で決めるので、CSP の `style-src 'unsafe-inline'` が必要（ARCH:116）。スクリプトほどの危険はないので受け入れる【推論】。
- 【事実】出典表示で `innerHTML` を使う（ARCH:135）ため、Trusted Types は入れない（ARCH の判断どおり）。
- 地図を使うのは「場所を選ぶ」画面と「道詳細の小さな地図」の2か所だけ（C-06, C-21）。jsdom のテストでは今の `leaflet-mock` を使い、本物の動きは E2E（地理院タイルは見本の画像に差し替える。ARCH:493）で確かめる。

### 2.3 CSP を「ヘッダー＋ページ内の meta」の2段にする方式

- 【事実（W3C CSP の仕様。今回は原文を開き直していない）】`<meta http-equiv="Content-Security-Policy">` では `frame-ancestors`・`report-uri`・`sandbox` が効かない。また meta より前に書かれた部分には効かない。
  - → ARCH の設計（`frame-ancestors 'none'` と `X-Frame-Options: DENY` をヘッダーに置く。meta を `<head>` の最初に入れる。ARCH:103-105）は、この制限に合っている。
- 【事実（同仕様）】ポリシーが2つあると、ブラウザは両方を満たすものだけを動かす。ヘッダーが `'unsafe-inline'` で緩くても、meta のハッシュで締まる（ARCH:104）。
- 危ないところ:
  1. **後処理が meta を入れ損ねると、黙って弱くなる**（ARCH:106, R7）。→ `verify-out.mjs` を CI の必須の関門にする（ARCH の案どおり）。全 HTML（`404.html` を含む）で確かめる。
  2. **Vercel が後処理の結果を配るか未確認**（C-34）。→ `"framework": null` ＋ `outputDirectory: "out"` で試す。
  3. **違反の報告先がない**（meta では `report-uri` が効かず、ヘッダー側に置いても受け取るサーバーがない）。→ E2E で `securitypolicyviolation` を数えて0件を確かめる（ARCH:494）で代わりにする。
  4. **開発サーバー（`next dev`）では CSP がかからない**。→ CSP の確認は「ビルドした `out/` を静的サーバーで配った E2E」だけで行う（ARCH:470）。監査06 B-M9（E2E が開発サーバーで動いている）もこれで直る。
- 判定: **方式は筋が通っている。ただし Step 0 で実物を確かめるまでは「計画」にすぎない。**
