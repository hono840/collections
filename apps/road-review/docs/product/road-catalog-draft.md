> **この案の限界（先に書く）**
> 1. **規制の確認は半分ほどしかできていない。** このセッションは Web 検索の上限（200回）に達していて、確認の担当は検索なしで Wikipedia と、分かっている公式ページを直接開くことしかできなかった。規制 133 項目のうち **公式ページで確かめた【事実】は 61、Wikipedia だけ・出典なしの【未確認】が 72**。規制が1つも書けていない道が 23 本ある（＝「規制なし」ではなく「未確認」）。
> 2. **走り屋・暴走の確認は 3 本しか出典がない。** 報道・警察のページを探す検索ができなかったため。ほかの道で「問題なし」と確かめたわけではない（証拠がないだけ）。
> 3. **区間（どこからどこまで）は、まだ人が決めていない。** OSM の線は「名前で拾った線」「峠から半径 N km で切った線」「手で決めた四角の範囲の国道」のどれかで、名所の区間と一致していないものが多い。長さは参考値。
> 4. 選定は【推論】（有名さの根拠として Wikipedia・観光協会・道路管理者のページを1つずつ付けた）。人気の順位や「日本風景街道」との照合はしていない（風景街道のページは前回の調査で 404）。

## 0. まとめ（中学生向けに）

**ゴール**: 検索で「ヤビツ」と打てば道が出る、その「道の名簿」の最初の 100 本を決めること。
→ **そのために**、全国（北海道〜沖縄）から有名な峠・スカイライン・海岸線・林道を **101 本**選び、1 本ずつ「呼び名・読み・別名・都道府県・区間・規制・選んだ理由」を付けた。
→ **そのために**、OpenStreetMap（OSM。みんなで作る地図データ）から道の線を探し、**98 本で線が見つかった**（うち 1 本は一部だけ）。見つからなかったのは 3 本（三国峠（北海道）・奥琵琶湖パークウェイ・生月サンセットウェイ）。
→ **ただし**、規制（冬の通行止め・有料・マイカー規制・二輪禁止・夜の通行止め）は公式ページで確かめられたものが約半分。アプリに出す前に、残りを確かめる作業が要る。
→ **CEO に決めてほしいこと**は 5 章（24 本）。特に **乗鞍スカイライン・乗鞍エコーラインは自家用車もバイクも通れない**（バス・タクシーのみ）ので、外すかどうか。

## 1. 表の読み方

- **OSM**: ○＝線が見つかった（長さは線から計算した km。上り下りが別の線になっている所は半分として数えた）。「峠±4km」＝峠の点から半径 4km で切った長さ（名所区間ではない）。`r数字`＝relation（道のまとまり）の番号、`w×数字`＝way（線）の本数。番号の一覧と、使った問い合わせ（query）は JSON の `osm` にある。
- **規制・注意**: リンク付き＝公式ページ（道路管理者・道路公社・料金所の運営・自治体・観光協会）を開いて確かめた【事実】（確認日 2026-10-10）。**【未確認】**＝Wikipedia だけ、または出典なし。セルが「【未確認】」だけ＝規制を1つも確かめられていない（「規制なし」ではない）。
- **選定理由**: リンク先は有名さの根拠（Wikipedia／観光協会／道路管理者）。文は自分の言葉で書き、出典の文章は写していない。
- ⚠ ＝安全上の問題（取締り・事故多発）を公的機関か報道で確かめた道（4 章）。

## 2. OSM から線を取った方法（再現できるように）

- 【事実】Overpass API（OSM のデータを条件で探せる公開サーバー）に、**地方ごとにまとめて 1 回ずつ**問い合わせた（8 地方＋取りこぼしの補い 2 回＝成功 10 回。ほかにサーバー混雑の 504 エラーが 3 回あり、30〜90 秒あけて再試行）。データ時点は 2026-10-10T04:31〜04:52Z。通信の名乗り（User-Agent）は `road-review-data-curation/0.1 (+https://github.com/hono840/collections)` で、個人の情報は入れていない。
- 問い合わせ文と結果（生データ）: `/private/tmp/claude-501/-Users-hiro-dev-collection/2ab04b8c-1720-4813-b6f8-2c054c1ad711/scratchpad/roaddata/`（`reg_*.overpassql`／`reg_*.json`／`reg_fix1`・`reg_fix2`）。照合のスクリプトは同じ場所の `spec.py`（候補の一覧）・`match.py`（照合と長さの計算）・`build.py`（この表と JSON を作る）。
- 線の取り方は 5 種類（JSON の `osm.method`）:
  - **N**: 道の名前（`name`/`alt_name`/`official_name`/`loc_name`/`bridge:name`）で探す。
  - **R**: 道のまとまり（route relation）の名前で探す。
  - **P**: 峠の点（`mountain_pass=yes`）を探し、そこを通る路線番号の道を半径 N km で切る。
  - **B**: 手で決めた四角の範囲の中の、路線番号の道（範囲は人の手で決めたので端は未調整）。
  - **BETWEEN**: 2 つの峠の点（例: 戸田峠と土肥峠）の間の路線番号の道。
- **長さの答え合わせ**【事実】: 箱根スカイライン 5.0km（Wikipedia 5km）、芦ノ湖スカイライン 11.0km（公式 10.7km）、伊豆スカイライン 40.3km（約40km）、西伊豆スカイライン 10.0km（10.8km）、知床横断道路の峠±6km 23.1km（23.8km）、角島大橋 1.8km（1,780m）、伊良部大橋 3.5km（3,540m）、古宇利大橋 2.0km（1,960m）、剣山スーパー林道 84.6km（約88km）。名前や relation で取った道は、長さがおおむね合っている。
- **ずれが大きいもの**【事実】: 路線全体を拾ったもの（赤城道路・奥多摩周遊道路・椿ライン・やまなみハイウェイなど）は名所区間より長い。碓氷峠は旧道とバイパスが混ざっている可能性が高い。安芸灘とびしま海道は 1.8km 分しか取れていない。各道の注意は JSON の `osm.note`。

### 5.1 全体として決めてほしいこと
1. **乗鞍の 2 本を外すか**: 乗鞍スカイライン（岐阜県の公式ページで「マイカー通行不可」）と乗鞍エコーライン（長野県の公式ページで三本滝ゲートより上は一般車両通行禁止）。【推論】このアプリは「自分で走った道を記録する」ので、外すか、「バス・自転車でのみ行ける道」と分かる表示にするのがよい。エコーラインは区間を「乗鞍高原〜三本滝」に縮めれば残せる。
2. **二輪が通れない道の扱い**: 信貴生駒スカイライン（二輪は全面禁止・公式）、白山白川郷ホワイトロード（二輪禁止・公式）、奥只見シルバーライン・弥彦山スカイライン（二輪禁止・Wikipedia のみ）。車の人は走れるので残し、「二輪通行不可」を目立たせる案【推論】。
3. **規制が【未確認】の道をアプリに出すとき**: 「規制は未確認。出かける前に道路管理者のページで確認」と出す（研究資料 7.3 の考え方）。72 項目・79 本が対象。
4. **残りの規制の確認をいつ・誰がやるか**: Web 検索が使えるセッションで、未確認の 72 項目を道路管理者のページで確かめ直す必要がある（1 本あたり 1〜3 回の確認）。
5. **区間を決める作業**: 峠（P）と範囲指定（B）の 35 本前後は、名所の区間（起点・終点）を決めて線を切り直す必要がある。線の形をアプリに入れる前の作業。
