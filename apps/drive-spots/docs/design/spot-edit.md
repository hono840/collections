# スポットの編集と「降りるIC」 見た目の仕様

- 書いた日: 2026-10-28 ／ 書いた人: ui-ux-designer
- 対象: `docs/product/plan-v2.md` の「作る順番」2（登録したスポットの全部の項目を編集できる＋「降りるIC」の欄）。受入条件は `spec.md` の AC41〜AC48。この文書は見た目・文言・フォーカスだけを決める。
- 原本 `Main.dc.html` に編集の画面は無い。なので原本にある部品だけで組み立てる（追加画面 `SpotFormScreen`・詳細の `InfoTile`・一覧の `SpotCard`・文字だけのボタン）。
- 新しい色・フォント・角丸・影・動き・アイコンは足さない。`globals.css` は変えない。画面の切り替えは一瞬（動きなし。アプリ全体に動きが無いため）。
- 新しい項目のデータ上の名前は `exitInterchange`（`''` = 未入力）。省略しない名前にした（`exitIc` にしない）。`version` 2 への引っ越しは `architecture.md` に書いてある。

## 決めたこと（ひとこと）

詳細画面の右上（いま空いている所）に、灰色の文字ボタン「スポットを編集」を置く。押した先の画面の題も「スポットを編集」。ボタンの文字と行き先の題を同じ言葉にする（一覧の「スポットを追加」→ 追加画面の題「スポットを追加」と同じ決まり）。メモの横のオレンジの「編集」とは、文字・色・場所の3つで分ける。

「降りるIC」は、どの画面でも「地域・距離」のすぐ下に置く（どこにある → どれくらい → どこで高速を降りる、の順）。一覧のカードでは「小田原西ICで降りる」と、自分あてのメモのような1文で出す。これがこの機能でいちばん覚えてもらいたい所（ドライブの「帳面」らしい書き方）。

## 1. 詳細画面の「スポットを編集」ボタン

- 場所: 上の帯の右端（戻るボタンと同じ行）。帯は今の `flex items-center px-3` のまま。ボタンに `ml-auto` を付けて右へ寄せる。
- 見た目: 文字だけのボタン。15px・`font-medium`・`text-ink-soft`（灰色）。高さ 44px（`h-11`）、幅 44px 以上（`min-w-11`）、左右の余白 `px-2`。帯の `px-3`（12px）＋ボタンの `px-2`（8px）＝ 20px なので、文字の右端が下の箱（地域・距離・メモ）の右端とそろう。
- 幅の見積もり【推論】: 7文字 × 15px ＋ 余白 16px ＝ 約121px。戻るボタン 44px と並べても、320px の画面でも1行に入る。
- 灰色にする理由:
  - 上の帯は「別の画面へ移る」場所（左は「一覧にもどる」）。一覧の右上の「バックアップ」も、別の画面へ移る灰色の文字ボタン。同じ決まりにそろえる。
  - オレンジの文字は「その場で書く・決める」操作（メモの「編集」、追加画面の「保存」）に残す。オレンジの「編集」が1つの画面に2つ並ばないようにする。
- 15px にする理由: 押した先（編集画面）の上の帯の「キャンセル」「保存」も 15px。押す前と後で、同じ場所に同じ大きさの文字がつながる。一覧の「バックアップ」が 13px なのは見出しと1行に並べるためで、ここには並べる物が無い。
- 読み上げ名: 見えている文字「スポットを編集」がそのまま名前。`aria-label` は付けない。
- 2つの「編集」の見分け:

| | スポットを編集（新しい） | メモの編集（今のまま、AC29） |
| --- | --- | --- |
| 見える文字 | スポットを編集 | 編集 |
| 読み上げ名 | スポットを編集 | メモを編集 |
| 場所 | 上の帯の右端 | 見出し「メモ」の右 |
| 色・太さ | 灰色 `text-ink-soft`・`font-medium` | オレンジ `text-accent`・`font-bold` |
| 押すと | 編集画面へ移る | その場でメモ欄が入力欄になる |

  - 見える文字が違うので、色が見分けにくい人にも分かる（色だけに頼らない）。
  - WCAG 2.5.3（見えている文字を読み上げ名に含める）: 新しいボタンは「見える文字 ＝ 名前」なので満たす。W3C の解説は「見えている文字を名前の最初に置くのがよい」としていて、それも満たす（出典: [W3C Understanding SC 2.5.3](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html)）。メモの「メモを編集」は見える文字が名前の最後に来るが、AC29 で決まっているので変えない。
  - 声で操作する人は「スポットを編集」と言えば、メモのボタンと取りちがえない。【未確認】「編集」とだけ言ったときにどちらが選ばれるかは、端末によって違う可能性がある。
- キーボードの順番: 一覧にもどる → スポットを編集 →（名前の見出しは Tab で止まらない）→ 編集（メモを編集）→ 行った！にする → このスポットを削除。
- フォーカスの見た目は今の全体ルール（オレンジの線 2px・2px 離す）。ホバーの見た目は足さない（ほかのボタンにも無い）。押せない状態は作らない。
- メモの編集中も、このボタンは出したまま。押したら、戻るボタンと同じく打ちかけのメモは捨てて編集画面へ移る（AC25「別の画面への移動」）。編集画面のメモ欄には、保存してあるメモが入る（→「相談したいこと」2）。
- 削除の1回目の状態（AC8）は、詳細を離れるので解除される（今の作りのまま）。戻ってきたときは「このスポットを削除」。

## 2. 編集画面（SpotFormScreen をそのまま使う）

- 見た目は追加画面と同じ。違うのは「題」と「最初から値が入っていること」だけ。
- 上の帯: 「キャンセル」｜「スポットを編集」｜「保存」。題は h1・17px・太字・中央（今のクラスのまま）。「スポットを追加」と同じ7文字なので幅も同じで、新しい崩れは出ない。
- 下の大きいボタン: 「保存する」（追加画面と同じ文字・同じ見た目）。
- 最初に入っている値:
  - スポット名・地域・片道の距離・降りるIC・おすすめ時期・メモ: 保存されている文字そのまま。
  - 種類: 保存されている種類のチップが選ばれた状態（今の `Chip variant="choice"` のまま）。
  - 地域が `'未入力'` ちょうどのとき: 欄は空にする。薄い文字「例：神奈川」が見える。空のまま保存すると、また `'未入力'` になる（追加と同じ）。
  - 距離・降りるIC・時期・メモが空のとき: 欄は空（それぞれの薄い文字が見える）。
- 欄の並び（追加画面も編集画面も同じ）:
  1. スポット名（必須）
  2. 種類
  3. 地域 ｜ 片道の距離（km）（2列のまま）
  4. **降りるIC**（新しい。横いっぱい）
  5. おすすめ時期
  6. メモ
  7. 保存する
- 降りるIC をここに置く理由: 「どこにある（地域）→ どれくらい（距離）→ どこで降りる（IC）」と、行き方の情報がひとかたまりになる。そのあとに「いつ（時期）」「ひとこと（メモ）」が続く。詳細画面の箱も同じ順にする（3章）。
- 横いっぱいにする理由: 「おすすめ時期」と2列にすると、時期の薄い文字「例：紅葉の季節、早朝」が半分の幅に入りきらない。距離と組みかえると、今の「地域 ｜ 距離」の組が崩れる。
- 降りるIC の欄:
  - `FormField`（1行の `TextField`）。ラベル「降りるIC」、薄い文字「例：小田原西IC」。
  - `inputMode` は付けない（ふつうの文字のキーボード）。
  - 必須ではない。エラーは無い。文字数の上限も無い（ほかの欄と同じ）。
  - 前後の空白は保存のときに削る（ほかの欄と同じ）。空白だけなら空になる。
  - 「IC」は半角の大文字。ラベル・薄い文字・一覧の文で同じ書き方にそろえる。
- エラー: 追加画面と同じ（AC10・AC11）。文言も同じ。「保存」と「保存する」の両方で検査する。
- キャンセル: 確認なしで、入力を捨てて詳細画面へ戻る（追加画面と同じ）。保存してあるデータは何も変わらない。

## 3. 詳細画面の「降りるIC」の箱

- `InfoTile` を1つ足す。ラベル「降りるIC」。値は入力したそのまま（例「小田原西IC」。「で降りる」は付けない。ラベルが言っているため）。空なら「未入力」（距離・時期と同じ `NOT_ENTERED`）。
- 置き場所: 「自宅からの距離（片道）」の次、「おすすめ時期」の前。横いっぱい（`wide`）。

```
┌ 地域 ───────┐┌ 自宅からの距離（片道） ┐
│ 神奈川       ││ 約 60 km              │
└──────────┘└───────────┘
┌ 降りるIC ────────────────────┐
│ 小田原西IC                              │
└────────────────────────┘
┌ おすすめ時期 ──────────────────┐
│ 未入力                                  │
└────────────────────────┘
```

- 横いっぱいにする理由: 原本では「おすすめ時期」が横いっぱい。「半分の箱2つ＋横いっぱいの箱」という原本の形をくずさずに足せる。また IC の名前は「東名高速 大井松田IC」のように長くなることがあり、半分の幅（16px 太字で約8文字）だと2行になりやすい。
- ラベルは追加画面と同じ「降りるIC」。（距離の箱のラベルが追加画面と違うのは原本どおり。新しい項目は同じ言葉にそろえる）
- 読み上げ: `dl` の中で 地域 → 自宅からの距離（片道）→ 降りるIC → おすすめ時期 の順に読まれる。
- 高さ【推論】: 箱が1段（約85px）増える。390×844 で名前1行・メモ1行なら、下の「このスポットを削除」まで約710pxで1画面に入る。入らないときは今と同じく中だけスクロールする。

## 4. 一覧のカード

- 降りるIC が入っているときだけ、「地域・種類」の下に1行足す。文は「{降りるIC}で降りる」。例「小田原西ICで降りる」。
- 空（`''`）なら、この行は作らない（空の行・すき間も残さない）。今のカードと見た目は変わらない。
- 見た目: 「地域・種類」の行と同じ。13px・`text-ink-muted`・`wrap-anywhere`（長いと折り返す。切らない）。行の間は今の入れ物の `gap-1`（4px）のまま。
- 「降りるIC：小田原西IC」のような「ラベル：値」の形にしない理由:
  - 「IC」が2回出る（ラベルにも値にも入るため）。小さなカードでは読みにくい。
  - 値が先に来るので、一覧をざっと見るときに IC の名前がすぐ目に入る。
  - 「〇〇ICで降りる」は、車で出かける人がふだん使う言い方。読み上げも自然な文になる。
- 「地域・種類」の行に「・」でつなげない理由: 「神奈川・絶景ロード・小田原西IC」では、最後が何の名前か分からない。また長くなって、375px の幅でほぼ毎回折り返す。
- 折り返す理由（切らない）: 「地域・種類」の行も折り返している。切ると後ろの「で降りる」が消えて、何の名前か分からなくなる。
- 幅の見積もり【推論】: 375px の画面で、カードの文字が入る幅は約215px（行ったのチェック印があると約179px）。13px なら約13〜16文字。「小田原西ICで降りる」（約9文字分）は1行に入る。
- カードの高さ: 行が1つ増えると約23px高くなる。左のマーク（44px）は今のまま上下の真ん中（`items-center`）。
- 読み上げ: カードは1つのボタンで、中の文字が順に名前になる。「箱根ターンパイク 神奈川・絶景ロード 小田原西ICで降りる」。マーク・チェック印・矢印は今のまま読まれない（`aria-hidden`）。
  - 【推論】実際のブラウザは縦に並んだ行の間に区切りを入れて読むことが多い。テスト（jsdom）では区切りが入らないので、テストは今と同じく `\s*` で受ける。
- 文は1つの文字のかたまりで出す（テンプレート文字列 `` `${exitInterchange}で降りる` ``）。`getByText('小田原西ICで降りる')` で確実に見つかるようにするため。
- 一覧のテストがカードを見分けるのに使っている「・種類」（`CATEGORY_LINE_PATTERN`）は、この行を足しても変わらない。

## 5. フォーカスと読み上げ

| とき | フォーカス | 読み上げ |
| --- | --- | --- |
| 詳細で「スポットを編集」を押す | 編集画面の題 h1「スポットを編集」（`tabIndex={-1}`。追加画面と同じ） | 題が読まれる |
| 「保存」か「保存する」で保存できた | 詳細画面の「スポットを編集」ボタン | ボタン名が読まれる。「保存しました」のお知らせは出さない（追加・メモの保存と同じ） |
| 「キャンセル」 | 詳細画面の「スポットを編集」ボタン | ボタン名が読まれる |
| 保存したが、名前が空・距離がまちがい | 最初のまちがった欄（名前 → 距離の順）。画面は移らない | 欄の名前とエラー文（`aria-describedby`。追加画面と同じ） |
| 編集中に、別のタブでこのスポットが削除された（`storage` イベント） | すぐに一覧へ。一覧の見出し「ドライブスポット帳」。入力は捨てる | 見出しが読まれる |
| 保存の直前の読み直しで、このスポットが無くなっていた（AC22・AC27 と同じ） | 一覧の見出し「ドライブスポット帳」。何も保存しない（よみがえらせない） | 見出しが読まれる |
| 編集から戻った詳細で「一覧にもどる」 | 一覧のそのカード（今と同じ）。種類を変えて今の絞り込みに出なくなったときは見出し（今と同じ） | — |

- 戻ってきたときに「スポットを編集」へ戻す理由: このアプリは「開いた物に戻る」でそろえている（詳細 → 一覧は元のカード、メモの編集のあとは「編集」）。このボタンは上の帯にあってスクロールしないので、フォーカスがいつも見える所に来る。続けて読めば、変わった名前と箱の中身が読める。
- 詳細画面は戻るたびに作り直される（今の作り）ので、スクロールは一番上・メモは読む状態・削除は1回目の前に戻る。
- 一覧のタブと種類の絞り込みは、編集の保存では変えない（追加と違い、一覧へは戻らないため）。
- この端末で保存できない状態（AC15・AC30）でも、画面の上では変わる（AC28 と同じ扱い）。お知らせは今の一覧の場所だけ。編集画面には足さない。
- 【推奨・code-architect が確定】編集中に別のタブでこのスポットのほかの所（行った/行きたい・メモなど）が変わったとき:
  - 編集画面の入力欄は変えない（打っている文字を消さない）。最初の値は開いたときに1回だけ使う。
  - 保存すると、7つの欄（名前・種類・地域・距離・降りるIC・時期・メモ）はこの画面の値になる。行った/行きたい・ID・並び順・`nextId` は、読み直した最新のデータのまま。

## 7. クラス（そのまま使う）

```tsx
{/* 詳細: 上の帯 */}
<div className="flex items-center px-3 pb-2 pt-safe-bar">
  {/* 一覧にもどる: 今のまま */}
  {/* 見える文字がそのまま名前。aria-label は付けない */}
  <button type="button" ref={editSpotButtonRef} onClick={() => onEdit()}
    className="ml-auto h-11 min-w-11 bg-transparent px-2 text-15 font-medium text-ink-soft">
    スポットを編集
  </button>
</div>

{/* 詳細: 箱（地域と距離は今のまま） */}
<dl className="grid grid-cols-2 gap-2.5">
  {/* 地域 / 自宅からの距離（片道） */}
  <InfoTile label="降りるIC" value={spot.exitInterchange === '' ? NOT_ENTERED : spot.exitInterchange} wide />
  {/* おすすめ時期（今のまま） */}
</dl>

{/* 追加・編集: 「地域 ｜ 距離」の grid のすぐ下 */}
<FormField id={`${fieldIdPrefix}-exit-interchange`} label="降りるIC" placeholder="例：小田原西IC"
  value={input.exitInterchange} onValueChange={(value) => updateField('exitInterchange', value)} />

{/* 一覧のカード: 文字の入れ物の中 */}
<span className="flex min-w-0 flex-1 flex-col gap-1">
  <span className="truncate text-16 font-bold">{name}</span>
  <span className="text-13 text-ink-muted wrap-anywhere">{region}・{category}</span>
  {exitInterchange === '' ? null : (
    <span className="text-13 text-ink-muted wrap-anywhere">{`${exitInterchange}で降りる`}</span>
  )}
</span>
```

部品に足すもの（名前は例。code-architect が決める）:

- `SpotFormScreen`: 題（`'スポットを追加'` ／ `'スポットを編集'`）と、最初の値（例 `initialInput?: SpotInput`。無ければ今の空の入力）。最初の値は `useState` の初期値として1回だけ使う。見た目のクラスは変えない。
- 地域の `'未入力'` → `''` は、`spots.ts` の純粋な関数（例 `spotToInput(spot)`）で行うのがおすすめ（テストしやすいため）。保存のときの `''` → `'未入力'` は `addSpot` と同じ処理を使う。
- `SpotDetailScreen`: `onEdit: () => void` と、戻ってきたときに「スポットを編集」へフォーカスするための指定（`architecture.md` で `focusTarget?: 'heading' | 'editSpot'` に決定）。
- `SpotCard`: `exitInterchange: string`（`''` なら行を出さない）。
- `DriveSpotsApp`: 画面に `'edit'` を足す。編集中も `selectedSpotId` はそのまま（あとで一覧へ戻ったとき、元のカードにフォーカスするため）。今の「詳細のスポットが無くなったら一覧へ」の判定を、`'edit'` にも同じく効かせる。

## 確かめること

- 【推論】幅の計算は、かな・漢字1文字 ＝ 1em、半角英字は約0.6em の前提。375px と 390px で、上の帯の「スポットを編集」が1行に入るか、カードの「…で降りる」が1行に入るか（チェック印ありも）をブラウザで見る。
- 色の見やすさ（計算値）: 「スポットを編集」の灰色と背景 約12:1、カードの3行目（`text-ink-muted` とカードの色）約7.4:1、箱の文字は今と同じ。どれも 4.5:1 以上。
- 【未確認】iPhone の VoiceOver で、カードが「名前、地域・種類、…で降りる」と区切って読まれるか。
- 今のテストへの影響: 詳細画面のボタンが1つ増える。`getByRole('button', { name: /編集/ })` のようなゆるい探し方は2つ当たるので、名前は完全一致（`'スポットを編集'` ／ `'メモを編集'`）で探す。追加画面の欄は `getByLabelText('降りるIC')` で探せる。

## 相談したいこと

1. **別のタブで削除されたとき、だまって一覧へ戻る（打った内容が消える）。** 理由が分からないまま入力が消えるので、「入れたはずの変更が消えた」と思われやすい。案: 一覧の上（AC15 のお知らせと同じ場所・同じ箱）に「編集していたスポットは、ほかのタブで削除されました」と出す。ただ、1人で使うアプリで2つのタブを同時に開くことはまれなので、今回は決まったとおり（だまって戻る）でもよい。出すなら、詳細画面（AC27）にも同じ文をそろえる。
2. **メモの編集中に「スポットを編集」を押すと、打ちかけのメモが消える**（AC25 の「別の画面への移動」）。「ついでにほかの所も直そう」と思って押した人ほど損をする。案: 打ちかけのメモを、編集画面のメモ欄に入れた状態で開く。キャンセルすれば今と同じく何も保存されない。この文書では、今の決まり（捨てる）で書いてある。
