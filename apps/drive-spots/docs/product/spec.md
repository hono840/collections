# ドライブスポット帳 仕様（v1）

行きたい道（峠・絶景ロードなど）を自分用にメモし、行ったら「行った」に移すスマホ向けアプリ。

- **デザイン原本**: `docs/design/Main.dc.html`（Claude Design のキャンバス、390×844）。見た目・文言・色・余白はこれに合わせる。原本の `class Component` の中身が画面の動きの正解。
- **公開先**: GitHub Pages `https://hono840.github.io/collections/drive-spots/`（静的書き出し・サーバーなし）
- **保存**: 端末の中（localStorage）。ログインなし。外部への通信なし。

## 対象外（v1 では作らない）

ログイン・端末間の同期・写真・地図・検索・並べ替え・登録済みスポットのメモ以外の編集（デザインに無いため）・PWA。メモの編集は AC23〜AC29（2026-10-25 に追加。計画は `plan-v2.md` の段階1）。

## 受入条件

| ID | 条件 |
| --- | --- |
| AC1 | 保存データが無い初回は、デザインの初期データ19件が「行きたい」にデザインの順で並ぶ。 |
| AC2 | タブ「行きたい N」「行った N」で切り替わる。N はカテゴリ絞り込みに関係なく全体の件数。選択中の色は 行きたい = `#FF7A1A`、行った = `#5AA9FF`。 |
| AC3 | カテゴリチップ「すべて / 峠 / 絶景ロード / 海沿い / サーキット / 都市高速」で絞り込める。タブとの AND 条件。 |
| AC4 | 一覧カードにマーク（峠→峠、絶景ロード→景、海沿い→海、サーキット→走、都市高速→高）、名前（1行で省略）、「地域・種類」、行った ならチェック印。カードを押すと詳細へ。 |
| AC5 | 表示が0件なら「まだありません」とデザインの説明文を出す。 |
| AC6 | 詳細に 種類バッジ・行ったバッジ（行った時だけ）・名前・地域・片道距離（「約 N km」、空なら「未入力」）・おすすめ時期（空なら「未入力」）・メモ（空なら「メモはまだありません」、改行を保つ）を出す。戻るボタンの読み上げ名は「一覧にもどる」。 |
| AC7 | 「行った！にする」と「「行きたい」に戻す」で状態が切り替わり、タブの件数と中身がすぐ変わる。 |
| AC8 | 「このスポットを削除」は2回押しで削除する。1回目でボタンの文字が「もう一度押すと削除します」に変わり、2回目で削除して一覧へ戻る。詳細を離れたら1回目の状態は解除。ブラウザの確認ダイアログ（`confirm`）は使わない。 |
| AC9 | 右下の「スポットを追加」から追加画面へ。項目は スポット名（必須）・種類（初期値 峠）・地域・片道の距離（km）・おすすめ時期・メモ。「キャンセル」で一覧へ戻り、入力は捨てる。 |
| AC10 | 保存（ヘッダーの「保存」と下の「保存する」の両方）で、名前が空または空白だけなら「スポット名を入れてください」を出して保存しない。名前を入力し直すとエラーは消える。 |
| AC11 | 距離は 空 か 0以上の普通の数字（`60`、`12.5` のような半角の10進数。`1e3`・`0x10`・`.5`・`-0`・全角数字は不可）だけ受け付ける。それ以外は「0以上の数字を入れてください」を出して保存しない。 |
| AC12 | 保存に成功すると一覧の先頭に追加され、タブは「行きたい」、カテゴリは「すべて」に戻る。前後の空白は削る。地域が空なら「未入力」。 |
| AC13 | 追加・行った切り替え・削除のたびに localStorage に保存し、再読み込みしても残る。キーは `drive-spots:v1`、形は `{ "version": 1, "nextId": number, "spots": Spot[] }`。 |
| AC14 | 保存データが壊れている・形が違うときは初期データで起動し、元の文字列を `drive-spots:v1:backup` に退避する（消さない）。退避に失敗したときは元の文字列を上書きしない（保存しない）で、AC15 のお知らせを出す。 |
| AC15 | localStorage が使えない環境（例外が出る）でもアプリは動き、一覧の上に「この端末では保存できません（再読み込みで消えます）」と小さく出す。読み込みで例外が出たときは書き込みもしない（読めていないデータを上書きしない）。 |
| AC16 | 削除したスポットの ID は再利用しない（`nextId` は増えるだけ）。 |
| AC17 | スマホ幅では画面いっぱい、PC では幅 最大 480px で中央。高さは `100dvh`。iPhone のノッチとホームバー（safe-area）に重ならない。ページ全体は横スクロールしない（チップ列だけ横スクロール）。 |
| AC18 | ボタン・入力欄は本物の `button` / `input` / `textarea` と `label`。キーボードのフォーカスが見える。 |
| AC19 | フォントは Barlow Condensed（英字見出し・数字）と Zen Kaku Gothic New（本文）。ビルド時に取り込み、表示するときに外部へ通信しない。 |
| AC20 | GitHub Pages の配下パス `/collections/drive-spots/` で CSS・JS・フォントがすべて読み込める。 |
| AC21 | 外部への通信・トラッキングはゼロ。CSP は meta タグ（ハッシュ方式、road-review と同じ仕組み）で、スクリプトを自分のものだけに限る。 |
| AC22 | 2つのタブ、または「戻る/進む」で復元されたページで操作しても、別の場所で保存された新しいデータを消さない。保存の直前に最新のデータを読み直し、その上に変更を加える。別のタブで保存されたら（`storage` イベント）、また「戻る/進む」で復元されたら（`pageshow` の `persisted`）、表示も最新にする。 |
| AC23 | 詳細画面のメモ欄に「メモを編集」ボタンがある。押すとメモ欄が入力欄（`textarea`、いまのメモが入った状態）に変わり、「保存」「キャンセル」が出る。入力欄にフォーカスが移る。 |
| AC24 | 「保存」で詳細のメモが変わり、再読み込みしても残る。前後の空白は削る（追加のときと同じ）。途中の改行は残す。空にしてもよい（空なら「メモはまだありません」と出す）。保存のあと、フォーカスは「メモを編集」に戻る。 |
| AC25 | 「キャンセル」・戻るボタン・別の画面への移動では、編集中の内容を捨てる（保存しない）。キャンセルのあと、フォーカスは「メモを編集」に戻る。詳細画面を離れない操作（「行った！にする」など）では、編集中の内容を残す。 |
| AC26 | 変わるのはメモだけ。名前・種類・地域・距離・時期・行った/行きたい・ID・並び順・`nextId` は変わらない。 |
| AC27 | 保存は `updateSpotsData`（保存の直前に最新のデータを読み直す、AC22）を通す。別のタブで増えたスポットは消さない。別のタブでそのスポットが削除されていたら、よみがえらせない（詳細は閉じて一覧へ戻る）。 |
| AC28 | この端末で保存できない状態（AC15 のお知らせが出ている）でも、画面の上ではメモが変わる。追加・削除と同じ扱い。 |
| AC29 | ボタンと入力欄は本物の `button` / `textarea`。入力欄の読み上げ名は「メモ」、編集ボタンの読み上げ名は「メモを編集」。キーボードのフォーカスが見える。メモの編集を始めると、削除の1回目の状態（AC8）は解除する。 |

## 初期データ（AC1）

デザイン原本の `seed` 配列の19件そのまま（名前・地域・種類・メモ）。距離とおすすめ時期は空。ID は 1〜19、`nextId` は 20。

## 保存データの形（AC13）

```ts
type Category = '峠' | '絶景ロード' | '海沿い' | 'サーキット' | '都市高速'
type Spot = {
  id: number
  name: string
  region: string
  category: Category
  distanceKm: string // 空文字 = 未入力
  season: string
  memo: string
  done: boolean
}
```
