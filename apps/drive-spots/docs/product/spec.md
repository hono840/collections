# ドライブスポット帳 仕様（v1）

行きたい道（峠・絶景ロードなど）を自分用にメモし、行ったら「行った」に移すスマホ向けアプリ。

- **デザイン原本**: `docs/design/Main.dc.html`（Claude Design のキャンバス、390×844）。見た目・文言・色・余白はこれに合わせる。原本の `class Component` の中身が画面の動きの正解。
- **公開先**: GitHub Pages `https://hono840.github.io/collections/drive-spots/`（静的書き出し・サーバーなし）
- **保存**: 端末の中（localStorage）。ログインなし。外部への通信なし。

## 対象外（v1 では作らない）

ログイン・端末間の同期・写真・地図・検索・並べ替え・登録済みスポットのメモ以外の編集（デザインに無いため）・PWA。メモの編集は AC23〜AC29（2026-10-25 に追加。計画は `plan-v2.md` の段階1）。古い版の守り・バックアップ・名前の統一は AC30〜AC40（2026-10-25 に追加。経緯は `plan-v2.md` の「決まったこと」）。

| AC8 | 「このスポットを削除」は2回押しで削除する。1回目でボタンの文字が「もう一度押すと削除します」に変わり、2回目で削除して一覧へ戻る。詳細を離れたら1回目の状態は解除。ブラウザの確認ダイアログ（`confirm`）は使わない。 |
| AC9 | 右下の「スポットを追加」から追加画面へ。項目は スポット名（必須）・種類（初期値 峠）・地域・片道の距離（km）・おすすめ時期・メモ。「キャンセル」で一覧へ戻り、入力は捨てる。 |

| AC11 | 距離は 空 か 0以上の普通の数字（`60`、`12.5` のような半角の10進数。`1e3`・`0x10`・`.5`・`-0`・全角数字は不可）だけ受け付ける。それ以外は「0以上の数字を入れてください」を出して保存しない。 |
| AC12 | 保存に成功すると一覧の先頭に追加され、タブは「行きたい」、カテゴリは「すべて」に戻る。前後の空白は削る。地域が空なら「未入力」。 |
| AC13 | 追加・行った切り替え・削除のたびに localStorage に保存し、再読み込みしても残る。キーは `drive-spots:v1`、形は `{ "version": 1, "nextId": number, "spots": Spot[] }`。 |
| AC14 | 保存データが壊れている・形が違うときは初期データで起動し、元の文字列を `drive-spots:v1:backup` に退避する（消さない）。退避に失敗したときは元の文字列を上書きしない（保存しない）で、AC15 のお知らせを出す。 |
| AC15 | localStorage が使えない環境（例外が出る）でもアプリは動き、一覧の上に「この端末では保存できません（再読み込みで消えます）」と小さく出す。読み込みで例外が出たときは書き込みもしない（読めていないデータを上書きしない）。 |
| AC16 | 削除したスポットの ID は再利用しない（`nextId` は増えるだけ）。 `nextId` は 1,000,000,000 以下とし、それより大きい保存データやバックアップファイルは壊れているものとして扱う（ID が安全な整数の範囲を超えて重ならないように。2026-10-25 追加）。`nextId` が上限（1,000,000,000）に達しているデータには、それ以上スポットを追加しない（ふつうに使って届く数ではなく、細工したファイルを読み込んだときだけ起きるため、お知らせは出さない）。 |
| AC17 | スマホ幅では画面いっぱい、PC では幅 最大 480px で中央。高さは `100dvh`。iPhone のノッチとホームバー（safe-area）に重ならない。ページ全体は横スクロールしない（チップ列だけ横スクロール）。 |
| AC18 | ボタン・入力欄は本物の `button` / `input` / `textarea` と `label`。キーボードのフォーカスが見える。 |
| AC19 | フォントは Barlow Condensed（英字見出し・数字）と Zen Kaku Gothic New（本文）。ビルド時に取り込み、表示するときに外部へ通信しない。 |
| AC20 | GitHub Pages の配下パス `/collections/drive-spots/` で CSS・JS・フォントがすべて読み込める。 |
| AC21 | 外部への通信・トラッキングはゼロ。CSP は meta タグ（ハッシュ方式、road-review と同じ仕組み）で、スクリプトを自分のものだけに限る。 |
| AC22 | 2つのタブ、または「戻る/進む」で復元されたページで操作しても、別の場所で保存された新しいデータを消さない。保存の直前に最新のデータを読み直し、その上に変更を加える。別のタブで保存されたら（`storage` イベント）、また「戻る/進む」で復元されたら（`pageshow` の `persisted`）、表示も最新にする。 |
| AC23 | 詳細画面のメモ欄に「メモを編集」ボタンがある。押すとメモ欄が入力欄（`textarea`、いまのメモが入った状態）に変わり、「保存」「キャンセル」が出る。入力欄にフォーカスが移る。 |
| AC24 | 「保存」で詳細のメモが変わり、再読み込みしても残る。前後の空白は削る（追加のときと同じ）。途中の改行は残す。空にしてもよい（空なら「メモはまだありません」と出す）。保存のあと、フォーカスは「メモを編集」に戻る。 |
| AC25 | 「キャンセル」・戻るボタン・別の画面への移動では、編集中の内容を捨てる（保存しない）。キャンセルのあと、フォーカスは「メモを編集」に戻る。詳細画面を離れない操作（「行った！にする」など）では、編集中の内容を残す。 |
| AC26 | 変わるのはメモだけ。名前・種類・地域・距離・時期・行った/行きたい・ID・並び順・`nextId` は変わらない。 |
| AC27 | 保存は `updateSpotsData`（保存の直前に最新のデータを読み直す、AC22）を通す。別のタブで増えたスポットは消さない。別のタブでそのスポットが削除されていたら、よみがえらせない（詳細は閉じて一覧へ戻る）。 |
| AC28 | この端末で保存できない状態（AC15 のお知らせが出ている）でも、画面の上ではメモが変わる。追加・削除と同じ扱い。 |
| AC29 | ボタンと入力欄は本物の `button` / `textarea`。入力欄の読み上げ名は「メモ」、編集ボタンの読み上げ名は「メモを編集」。キーボードのフォーカスが見える。メモの編集を始めると、削除の1回目の状態（AC8）は解除する。 |
| AC30 | 保存データの `version` が 1 より大きい整数のとき（新しい版のアプリが保存したデータ）は、壊れたデータとして扱わない。退避（AC14）も上書きもせず、このページでは一切書き込まない。一覧の上に「新しい版のアプリで保存されたデータがあります。ページを再読み込みしてください（このままでは保存されません）」と出す（AC15 のお知らせの代わり）。画面には初期データを出し、操作は画面の上だけで効く。起動時の読み込み、保存の直前の読み直し（AC22）、`storage` / `pageshow` での読み直しのどれでも同じに扱う。 |
| AC31 | 一覧の見出しの横に「バックアップ」ボタンがあり、押すとバックアップ画面へ移る。バックアップ画面には「一覧にもどる」「ファイルに書き出す」「ファイルから読み込む」がある。「一覧にもどる」で一覧へ戻る。 |
| AC32 | 「ファイルに書き出す」で、画面に出ている今のデータを JSON ファイル `drive-spots-YYYY-MM-DD.json`（端末の日付）としてダウンロードする。中身は `{ "app": "drive-spots", "backupVersion": 1, "exportedAt": ISO 8601 の日時, "data": 保存データと同じ形 }`。保存できない状態（AC15）でも書き出せる。新しい版のデータがある状態（AC30）では、バックアップ画面にも AC30 のお知らせを出し、「ファイルに書き出す」と「ファイルから読み込む」は使えなくする（画面のデータは保存データと違うので、初期データだけのファイルが本物のバックアップのように作られないように）。外部への通信はしない。 |
| AC33 | 書き出した日時を `drive-spots:v1:last-backup` に残す。バックアップ画面の「最後に書き出した日」に「2026年10月25日（今日）」「2026年10月20日（5日前）」のように出し、一度もなければ「まだ書き出していません」と出す。日数は端末の暦の日付で数える。この記録が書けなくても、書き出しはそのまま行う。保存できない状態（AC15・AC30）で書き出したときは記録しない（書き出したのは画面の上だけのデータで、保存データとは違うため）。 |
| AC34 | 「ファイルから読み込む」でファイルを選ぶと、中身を変える前に検査する。1MB（1,000,000 バイト）より大きい →「ファイルが大きすぎます（1MB まで）」。形が違う・壊れている（`data` は AC13・AC14 と同じ厳しさで検査）→「ドライブスポット帳のバックアップファイルではないか、壊れています」。`backupVersion` か `data.version` が 1 より大きい →「新しい版のアプリで作られたファイルです。ページを再読み込みしてから、もう一度読み込んでください」。どの場合もデータは変えない。 |
| AC35 | 正しいファイルなら、置き換える前に中身を見せる。「2026年10月20日に書き出したファイル」「行きたい N / 行った N」と、「いまのデータ（行きたい N / 行った N）は、このファイルの中身に置き換わります。」。ボタンは「置き換える」と「やめる」。「やめる」と画面を離れたときは何も変えない。 |
| AC36 | 「置き換える」で、データをファイルの中身（`nextId` も含めてそのまま）に置き換えて保存し、「読み込みました（行きたい N / 行った N）」と出す。保存は `updateSpotsData` を通すので、AC14・AC15・AC30 の守りがそのまま効く。保存できなかったとき（AC15 の状態）は、その下に「この端末では保存できませんでした（再読み込みで消えます）」と出す。 |
| AC37 | ファイルの中身は文字としてだけ表示する（HTML として解釈しない）。ファイルを読むときも外部への通信はしない。 |
| AC38 | この端末に保存されたデータがあり、一度も書き出していないか、最後の書き出しから30日以上たっているときは、一覧の「バックアップ」ボタンに印を付け、読み上げ名を「バックアップ（まだしていません）」または「バックアップ（30日以上していません）」にする。それ以外の読み上げ名は「バックアップ」。 |
| AC39 | この端末に正しい保存データがまだ無いとき（初回など）は、一覧に「前に使っていたデータは「バックアップ」から読み込めます」と小さく出す（ホーム画面に追加したアプリは、Safari と保存場所が別のことがあるため）。保存できない状態（AC15・AC30）のときは出さない。 |
| AC40 | アプリの名前は、画面のどこでも「ドライブスポット帳」にそろえる。一覧の見出しは「ドライブスポット帳」、その上の小さな英字は「DRIVE SPOTS」（デザイン原本の「行きたい道ノート」「DRIVE LIST」から変更。2026-10-25 決定）。 |

## 初期データ（AC1）

デザイン原本の `seed` 配列の19件そのまま（名前・地域・種類・メモ）。距離とおすすめ時期は空。ID は 1〜19、`nextId` は 20。

## 保存データの形（AC13）

```ts
type Category = '峠' | '絶景ロード' | '海沿い' | 'サーキット' | '都市高速'
type Spot = {
  id: number
  name: string
  region: string
  category: Category
  distanceKm: string // 空文字 = 未入力
  season: string
  memo: string
  done: boolean
}
```

データの形を将来変えるときは、キー `drive-spots:v1` のまま `version` を上げる（古い版の画面が書き込まないように、AC30）。
