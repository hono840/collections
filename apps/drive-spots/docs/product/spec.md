# ドライブスポット帳 仕様

行きたい道（峠・絶景ロードなど）を自分用にメモし、行ったら「行った」に移すスマホ向けアプリ。

- **デザイン原本**: `docs/design/Main.dc.html`（Claude Design のキャンバス、390×844）。見た目・文言・色・余白はこれに合わせる。原本の `class Component` の中身が画面の動きの正解。
- **公開先**: GitHub Pages `https://hono840.github.io/collections/drive-spots/`（静的書き出し・サーバーなし）
- **保存**: 端末の中（localStorage）。ログインなし。外部への通信なし。

## 対象外（v1 では作らない）

ログイン・端末間の同期・写真・地図・検索・並べ替え・PWA。メモの編集は AC23〜AC29（2026-10-25 に追加。計画は `plan-v2.md` の段階1）。古い版の守り・バックアップ・名前の統一は AC30〜AC40（2026-10-25 に追加。経緯は `plan-v2.md` の「決まったこと」）。スポットの全部の項目の編集と「降りるIC」は AC41〜AC48（2026-10-28 に追加。計画は `plan-v2.md` の「作る順番」2、見た目・文言・フォーカスは `docs/design/spot-edit.md`）。

## 初期データ（AC1）

デザイン原本の `seed` 配列の19件そのまま（名前・地域・種類・メモ）。距離・降りるIC・おすすめ時期は空。ID は 1〜19、`nextId` は 20、`version` は 2。

## 保存データの形（AC13）

```ts
type Category = '峠' | '絶景ロード' | '海沿い' | 'サーキット' | '都市高速'
type Spot = {
  id: number
  name: string
  region: string
  category: Category
  distanceKm: string // 空文字 = 未入力
  exitInterchange: string // 降りるIC。空文字 = 未入力（version 2 で追加）
  season: string
  memo: string
  done: boolean
}
type SpotsData = { version: 2; nextId: number; spots: Spot[] }
```

データの形を将来変えるときは、キー `drive-spots:v1` のまま `version` を上げる（古い版の画面が書き込まないように、AC30）。

`version` 2 を書く版を公開するときの注意（2026-10-28、レビューで分かったこと）:

- 守り（AC30）が無い版（PR #180 の公開＝2026-10-28 12時15分ごろ より前に開いた画面）は、`version` 2 のデータを壊れたデータとして `drive-spots:v1:backup` に退避し、上書きする。新しく開いた画面なら初期データで、開いたままの画面ならその画面が持っている古いデータで、次の操作のときに上書きする。上書きされたデータは `version` 1 なので新しい版は正しいデータとして読み、お知らせは出ない（それまでの降りるIC・追加・編集が消える）。退避されたデータを画面から戻す方法は無い。
- 守りのある版（PR #180 のあと）は、`version` 2 のデータを「新しい版のデータ」として扱い、書き込まない（AC30）。
- ページは10分で新しい版に入れかわる（GitHub Pages の `cache-control: max-age=600`）が、開いたままの画面（Safari のタブ・ホーム画面のアプリ）は古いまま残る。そこで公開の前に、使っている端末のそれぞれ（Safari と、ホーム画面のアプリは別々）で: 古い画面を閉じて開き直す → 見出しが「ドライブスポット帳」で「バックアップ」ボタンがある（守りのある版の印、AC31・AC40）ことを確かめる → バックアップを書き出す。
- `version` 2 を書いたあとは、この版より前に戻さない（戻すと、守りのある版でも保存できない状態になり、守りの無い版ならデータを消す）。直すときは、`version` 1 と 2 を読める新しい版を出す。
