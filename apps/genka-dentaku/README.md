# 原価電卓（genka-dentaku）

> **仕入れ値を変えるだけ、全メニューの原価率が即わかる。**

円安と物価高で、仕入れ値は毎月のように動きます。でも「どのメニューが赤字か」「いくら値上げすれば原価率が戻るか」を都度計算し直すのは重労働です。**原価電卓**は、食材の仕入れ値を1つ直すだけで、それを使う全メニューの原価・原価率・粗利をその場で再計算します。POS契約も会員登録も不要。スマホとブラウザだけで完結し、レシピと仕入価格は端末の外に出ません。

対象は、居酒屋・カフェ・ラーメン・定食・バルなどを1〜3店舗営む個人経営のオーナーシェフ／店主、そして開業準備中の方です。

---

## 特徴

- **仕入れ値を1つ直すと全メニューが即再計算** — 食材の価格を更新した瞬間、その食材を使う全メニューの原価・原価率・粗利が再計算されます。再計算ボタンも再読み込みも不要。これがこのツールの核（wedge）です。
- **値上げシミュレーション** — 「原価率30%にするには何円？」を逆算します。目標原価率から推奨売価（税込併記）をその場で提示し、丸めた後の実効原価率まで確認できます。
- **原価率アラート** — 各メニューを信号色（緑／黄／赤）で表示し、危険なメニューを悪い順に並べ替え。集約バナーで「今どれだけ危ないか」がひと目でわかります。閾値は自由に変更でき、**無料**で使えます。
- **登録不要・データは端末内** — アカウント作成もインストールも不要。レシピと仕入価格はすべてブラウザの localStorage に保存され、サーバーへ送信されません。営業秘密は端末の外に出ません。
- **CSV / PDF 出力（Pro）** — 原価表を CSV（Excel-JP でも文字化けしない BOM 付き）で書き出し、メニュー原価シートを PDF 印刷できます。
- **JSON バックアップ／復元（無料）** — 全データを JSON で書き出して保管・復元。機種変更やブラウザ移行、万一のデータ消失にも備えられます。

## 技術スタック

| レイヤ | 採用 |
| --- | --- |
| フレームワーク | Next.js 16（App Router・`output: 'export'` 静的エクスポート） |
| UI | React 19 / TypeScript（strict） / Tailwind CSS v4 |
| 実行時検証 | zod（localStorage・インポートデータの検証＋型推論） |
| アイコン・ユーティリティ | lucide-react / clsx / tailwind-merge |
| 暗号（ライセンス） | Web Crypto Ed25519（ブラウザ標準・追加依存なし） |
| テスト | Vitest（単体） / Playwright（E2E） |
| 保存先 | ブラウザの localStorage のみ |
| ホスティング | Cloudflare Pages 無料枠（第一候補） |

### アーキテクチャ要点

- **ゼロランタイム新依存** — 新規 runtime 依存は 0。PDF は `@media print` ＋ `window.print()`、CSV は `Blob`、暗号は Web Crypto、日付は `Intl`、状態管理は `useLocalStorage` ＋ Context ＋ `useMemo` で、すべてブラウザ標準機能で賄っています。
- **完全クライアントサイド** — サーバー・DB・認証なし。server actions / API routes / middleware / ISR は不使用。全ページ静的 HTML で配信するため障害点が少なく、CDN で高速です。
- **派生値は保存しない** — 原価・原価率・粗利・信号色は永続化せず、常に純関数で算出します。これが「仕入れ値を直すと即再計算」を構造的に保証します。
- **webフォント不使用** — システムフォントスタックのみ。ビルド時フェッチ 0 で LCP 最速・CLS ゼロ。
- **UI は Atomic Design** — atoms ← molecules ← organisms ← templates。逆方向の依存は禁止です。

## 開発

前提: **Node.js >= 22 / pnpm >= 10.16**。パッケージマネージャーは pnpm に統一しており、npm / yarn / bun でのインストールは PreToolUse フックがブロックします。

```bash
# 依存インストール
pnpm install

# 開発サーバー起動（http://localhost:3000）
pnpm dev

# 単体テスト（Vitest）
pnpm test

# E2E テスト（Playwright）
pnpm e2e

# Lint
pnpm lint

# 本番ビルド（静的エクスポート → out/）
pnpm build
```

> 依存を追加する際は cooldown ポリシーに従います。公開直後のバージョンは `pnpm-workspace.yaml` の `minimumReleaseAge`（既定7日）が受動的に遅延させ、サプライチェーン攻撃を緩和します。新依存の追加時は supply-chain-auditor のレビューが必須です。

## 収益化セットアップ（運用手順）

このアプリはバックエンドを持たず、**Stripe Payment Link ＋ オフライン検証のライセンスキー**で課金します。以下は公開前に一度だけ行う初期設定と、購入ごとの運用フローです。

### 初期設定（公開前に一度）

**1. 署名鍵ペアを生成する**

```bash
pnpm mint-key -- keygen
```

出力された**公開鍵**を環境変数 `NEXT_PUBLIC_LICENSE_PUBLIC_KEY` に設定します（ビルド時にクライアントへ埋め込まれ、公開して安全です）。**秘密鍵**は `.secrets/` に書き出されます。`.secrets/` は git 管理外（`.gitignore` 済み）です。**秘密鍵は絶対にコミット・共有しないでください** — 漏れるとライセンスキーを偽造されます。

**2. Stripe Payment Link を2本作成する**

月額（¥980）と年額（¥9,800）の Payment Link を作成し、それぞれ環境変数 `NEXT_PUBLIC_STRIPE_LINK_MONTHLY` / `NEXT_PUBLIC_STRIPE_LINK_ANNUAL` に設定します。料金ページの購入ボタンがこのリンクに接続されます。

**3. 特定商取引法ページを記入する**

`/legal/tokushoho` の【要記入】箇所（**18箇所**：事業者名・所在地・連絡先・販売価格・支払方法・引渡し時期・返品条件など）を実際の情報で埋めます。有料販売には法的に必須のページです。

### 購入ごとの運用（MVP・手動）

**4. 購入通知を受けたらキーを発行してメール送付する**

Stripe の領収書メール／注文ID を受け取ったら、ライセンスキーを発行します。

```bash
pnpm mint-key -- mint --plan annual --ref <注文ID>
```

`--plan` は `monthly` または `annual`。`--ref` に Stripe の注文ID を入れると、購入識別子がキーに埋め込まれます（共有の心理的抑止）。出力された `GENKA-...` キーを Gmail などで購入者へ送付し、購入者は料金ページで入力すると Pro が解錠されます。

> **MVP 後の自動化**: 件数が増えたら、Stripe の `checkout.session.completed` webhook を Cloudflare Worker で受け、Worker が mint → メール自動送付に切り替えます（署名鍵は Worker Secret に保管）。クライアントは静的のまま、アプリ本体の改修は不要です。

## ライセンス方式

課金の解錠は、サーバーに問い合わせない**オフライン署名検証**で行います。

- **方式** — Ed25519 電子署名。ライセンスキーは `GENKA-{ペイロード}-{署名}` 形式で、ブラウザの Web Crypto が公開鍵で署名を検証します。改ざんされたキーは即座に無効と判定されます。
- **有効期間** — mint 時にキーへ有効期限を焼き込みます。月額は **38日**（30日＋約8日バッファ）、年額は **373日**（365日＋約8日バッファ）。末尾7日は「まもなく期限切れ」を知らせる更新バナー期間（**猶予 = 7日**）で、この間も Pro は継続します。
- **期限切れの挙動** — 期限を過ぎると **Free に降格**し、CSV/PDF・全メニュー一括適用・新規メニュー追加（3件超）が再ロックされます。ただし**データは常に保持**され、既存の4件以上のメニューも閲覧・編集できます。更新キーを入力すれば即 Pro に復帰します。
- **プラン／有効期限は保存しない** — 毎起動でキーの署名を検証して都度導出するため、localStorage を手編集しても Pro を維持できません（耐タンパーの下限を確保）。
- **割り切り** — クライアントサイド検証は devtools 等でバイパス可能ですが、バックエンドレスによる固定費 ≈¥0 と、データが端末外に出ないプライバシーという製品価値を優先した設計です（善意ユーザーモデル）。
